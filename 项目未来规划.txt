# Toy Browser 项目后续规划文档
> **文档版本**：v1.0
> **日期**：2026-10-02
> **当前状态**：P0–P16 已完成，345 条测试通过
> **文档目的**：定义 P17 及以后的总体方向、阶段拆分、验收标准与依赖关系
> **对应文件**：建议保存为 `toy-browser-py/ROADMAP-P17Plus.md`，与现有 `ROADMAP.md` 并列
---
## 0. 指导思想
### 0.1 当前定位
项目现状是一个**单机渲染管线 + 自研 JS 解释器**：
- ✅ 已具备：选择器/层叠玩具、flex/float/table/absolute/sticky、@media/@supports/@keyframes/transition、事件循环、命中测试、JS 到 ES 中级水平（class/解构/可选链/Map/Set/生成器前夜）、345 条测试的回归网。
- ❌ 未具备：网络、HTML5 容错解析、真实字体排版、GUI 外壳、安全模型。
### 0.2 后续方向的根本转变
**P0–P16 的逻辑是“横向堆特性”**（每阶段加一组 CSS/JS 特性，测试数稳步 +20）。
**P17 起转为“纵向补地基”**——判断标准从“又实现了什么特性”变为“**离一个能打开真实网页的浏览器还差什么**”。
### 0.3 里程碑总览
| 里程碑 | 名称 | 一句话目标 | 检收标准 | 覆盖阶段 |
|---|---|---|---|---|
| **M1** | 排版质变 | 渲染质量接近真实浏览器 | 中英混排 + 粗体 + 内联链接跨行的真实 HTML，观感与真浏览器基本无差 | P17–P20 |
| **M2** | 打开真实网页 | 地址栏输入 URL 能加载真实静态页面 | `python browser.py https://example.com` 正常渲染；容错解析不崩 | P21–P24 |
| **M3** | 浏览简单网站 | 可读、可跳转、有历史 | 手选 2–3 个简单真实站点（纯文风博客/文档页）浏览体验完整 | P25–P30 |
| **M4** | 日常可用外壳 | 有浏览器该有的样子 | 多标签、历史、书签、错误页、迷你 DevTools | P31–P32 |
| **M5（可选）** | 深而窄 | 选一个子系统做到极致 | 见 §5 | P33+ |
### 0.4 规划原则
1. **观感差距优先于特性数量**。文本排不好造成的损失 > 缺少 `auto-fit`。原推测的“P17 Grid 深化”方向放弃。
2. **每阶段仍保持 ~20 条测试**的惯例，测试轨迹从 345 起步，目标终点 665+。
3. **网络层测试使用本地 `http.server` 夹具**，保证离线可测、CI 稳定。
4. **标准库优先**（`ssl`/`http.client`/`fontTools` 可引入），手写与否在学习价值与进度间权衡，下文逐项标注。
5. **每个里程碑结束做一次重构窗口**，不新增特性，只消化技术债。

## 1. 阶段组 A：排版与文本（P17–P20）→ 里程碑 M1
> 目标：替换“内置点阵字体”的玩具路线，建立**真实字体 → 真实度量 → 真实行盒 → 真实断行 → 抗锯齿渲染**的完整排版链。
### P17：字体文件解析
**目标**：解析 TTF/OTF，按真实字形渲染文字。
**范围**：
- 解析 TTF/OTF 头部表：`head` / `cmap` / `glyf` / `loca` / `hmtx` / `hhea`
- `cmap` 逆向查询：字符 → glyph id
- glyph 轮廓提取（二次贝塞尔曲线），先以描边/多边形近似渲染，为 P20 光栅化铺路
- `hmtx` 读取 advance width，替换现有字符宽度估算
- `@font-face` 玩具升级为加载真实字体文件
- 字重家族匹配：`font-weight` 400/700 双字重文件切换
**实现选择**：建议引入 `fontTools` 读表（学习重点在“怎么用”而非“二进制格式怎么解”）；`glyf` 轮廓解析可手写以理解格式。二选一均可，测试不受影响。
**测试清单方向**（20 条）：
- cmap 查表正确性（ASCII / CJK 各若干）
- advance width 与真实字体度量一致
- 双字重切换
- 缺字形 fallback 到 .notdef
- 损坏字体文件不崩溃
- 端到端：指定字体渲染 + 截图对比
**验收**：渲染一段文字，字形与系统字体渲染对比肉眼可辨“同源”。
**测试目标**：345 → 365
---
### P18：文本度量与行盒模型
**目标**：建立规范意义上的 line box，解决内联布局的正确性。
**范围**：
- 字体度量：ascent / descent / line-gap，`line-height` 的半领导者模型
- 行盒构建：inline-level 盒子 → line box 的分配算法（简化 CSS2.1 §10.8）
- 内联元素跨行拆分：`<a>链接文字很长会跨行</a>` 正确拆分两半并各自绘制
- baseline 对齐：`vertical-align` 玩具版（baseline / top / middle）
- 行内图片参与行高
- `text-align` 作用于真实行盒
**依赖**：P17 的度量数据。
**测试清单方向**：
- 半领导者：行高 > 字号时文字垂直居中于行盒
- 内联元素跨行拆分后样式不丢
- 行内图片抬高行高
- baseline 对齐数学
- 端到端：多行混排截图
**验收**：一段混排 HTML 的行高、基线、跨行链接与真浏览器截图并排对比可读性一致。
**测试目标**：365 → 385
---
### P19：断行与 Unicode 处理
**目标**：真实可用的断行行为。
**范围**：
- UAX#14 简化版断行算法（按 break class 分级，实现常用类别即可）
- CJK 逐字断行 + 禁则处理（行首禁则字：`，。！」）`等；行尾禁则字：`「（` 等）
- 空白折叠规则修正（white-space 处理已有玩具，对齐规范）
- 软连字符 `&shy;` 与 `hyphens` 玩具
- `word-break` / `overflow-wrap` 补全
- 长单词溢出的最小处理
**测试清单方向**：
- 英文按词断行、超长词 overflow-wrap
- CJK 逐字断行
- 禁则：句号不出现在行首
- &shy; 生效
- 端到端：一段中日英混排长文正确断行
**验收**：粘贴 2000 字混排文章，无一行行首标点、无字符被截断。
**测试目标**：385 → 405
---
### P20：渲染质量与字重体系（M1 收官）
**目标**：像素层面的观感提升。
**范围**：
- 路径光栅化：二次贝塞尔曲线扫描线填充（替换 P17 的近似渲染）
- 灰度抗锯齿（coverage-based）
- `font-weight` 完整阶梯：合成粗体（描边加粗）作为无字重文件时的兜底
- 字体 fallback 链：指定字体 → 系统字体目录扫描 → 内置兜底
- `letter-spacing` / `text-rendering` 玩具
- **M1 里程碑重构窗口**：文本管线代码整理，度量模块独立成 `text/` 子模块
**测试清单方向**：
- 曲线字形光栅化边界像素（'O' 'S' 类字母）
- 抗锯齿灰度渐变
- 合成粗体 vs 真粗体文件
- fallback 链顺序
- 端到端：默认配置渲染无字体文件的页面不崩
**验收（M1 总检收）**：渲染一篇含中英文、粗体、斜体、内联链接跨行、CJK 禁则的真实 HTML 文章，与真浏览器截图并排，普通用户观感无明显差异。
**测试目标**：405 → 425

## 2. 阶段组 B：网络与真实 HTML（P21–P24）→ 里程碑 M2
> 目标：从“加载字符串/文件”到“输入 URL 加载真实网页”。
### P21：URL 与 HTTP/1.1 客户端
**范围**：
- URL 解析：scheme/host/port/path/query/fragment、相对 URL 解析（`urljoin` 规范）、URL 规范化
- HTTP/1.1 最小客户端：GET 请求头、`Host`、状态码分派（200/301/404/500）
- Content-Type 分派：`text/html` → 渲染管线；其他类型 → 下载/忽略
- 请求超时、连接错误 → 统一错误页渲染
- 测试夹具：本地 `http.server` 起测试服务器，端到端测试全离线
**实现选择**：先用 `http.client`，接口设计成可替换（为以后手写 socket 留口子）。
**测试目标**：425 → 445
---
### P22：HTTP 深化与子资源加载
**范围**：
- 重定向链（上限 5 层，循环检测）
- `Content-Encoding: gzip` 解压
- `Transfer-Encoding: chunked` 解析
- `<link rel=stylesheet>` / `<img src>` 子资源并发加载（**接入已有事件循环**，这是现有架构第一次真正发挥威力）
- 子资源加载失败不阻塞页面渲染
- 相对 URL 基于文档 base 解析（`<base>` 标签玩具）
**测试清单方向**：
- 本地夹具返回重定向链 / gzip / chunked 各若干条
- 样式表 404 时页面照常渲染
- 并发加载时序（用夹具延迟响应验证）
**测试目标**：445 → 465
---
### P23：HTTPS 与磁盘缓存
**范围**：
- TLS：`ssl` 标准库包裹 socket（暂不手写）
- 证书校验：默认开启，提供 `--insecure` 开关
- 启发式磁盘缓存：响应存盘，`Cache-Control: max-age` / `no-cache` 玩具实现
- `ETag` / `If-None-Match` 304 协商缓存
- 加载进度事件（接到现有事件循环 → 未来 GUI 进度条）
**测试目标**：465 → 485
---
### P24：HTML5 容错解析（M2 收官，硬仗）
**目标**：真实互联网的脏 HTML 不崩、不错位。
**范围**（实现 WHATWG 树构建算法的**简化子集**）：
- Void elements（`<br>` `<img>` `<input>` 等无闭合）
- 自动闭合纠错：`<p>` 遇块级元素自动闭合、`<li>` 遇 `<li>` 闭合、表格 foster parenting 玩具
- 格式化元素重构：`<b><i></b></i>` → 正确的 adoption agency 简化版
- 原始文本模式：`<script>` / `<style>` / `<textarea>` 内容不按 HTML 解析
- HTML entities 完整表（`&amp;` `&nbsp;` `&#x1F600;` 等）
- 注释、DOCTYPE、大小写不敏感标签名
- **M2 里程碑重构窗口**：Parser 独立成 `html/` 子模块，输入统一为字节流
**测试清单方向**：
- 20 条经典容错用例（来自 WHATWG spec 样例裁剪）
- 已有 345 条测试中的 HTML 样例全部回归通过（解析器替换不能破坏旧渲染）
- 端到端：`https://example.com` 与一个真实脏页面渲染
**验收（M2 总检收）**：`python browser.py https://example.com` 渲染正常；喂入 10 个真实网站的脏 HTML，全部不崩溃且 DOM 树合理。
**测试目标**：485 → 505
---
## 3. 阶段组 C：布局正确性与 JS/DOM 补全（P25–P30）→ 里程碑 M3
> 目标：真实网站的 CSS 布局对得上，交互闭环。
### P25：CSS 层叠与计算值完善
**范围**：
- specificity 三元组真实比较（现有为玩具版）：(inline, id, class+attr+pseudo-class, element+pseudo-element)
- `!important` 与来源级联（author/UA 玩具）
- 继承传播：非继承属性初始值、`inherit` / `initial` / `unset`
- shorthand 展开为 longhand
- computed value 管线：`em`/`%` 相对父级解析链
**测试目标**：505 → 525
---
### P26：块级布局修正
**范围**：
- Margin 折叠（相邻兄弟、父子、空块）
- BFC 规则：`overflow: hidden` 清浮动、BFC 不与 float 重叠
- 高度自适应：百分比高度链、`height: auto` 由内容决定
- `min-width` / `max-width` / `min-height` / `max-height` 约束
- 宽度解析：`auto` 的分配规则（CSS2.1 §10.3 简化）
**测试目标**：525 → 545
---
### P27：Flexbox 完整化
**范围**（从 P1 的“最小实现”升级到真实可用的完整子集）：
- `flex-grow` / `flex-shrink` / `flex-basis` 三值冻结与分配算法（对齐规范 §9.7）
- `flex-wrap` + 多行
- `justify-content` / `align-items` / `align-content` / `align-self` 全项
- 主轴/交叉轴方向：`row` / `column` / `reverse` 组合
- `order`、flex item 的 `min-width: auto` 隐含行为
**测试目标**：545 → 565
---
### P28：表单与交互真实化
**范围**：
- `select` / `checkbox` / `radio` / `file` 控件升级（可交互、有状态、样式可定制）
- 表单提交：GET（拼 query string）/ POST（接 P21 网络层）
- 字段序列化、`name`/`value` 收集
- focus / tab 顺序、`<label>` 关联
- `formaction` / `required` 玩具校验
**测试目标**：565 → 585
---
### P29：JS 引擎补全（从玩具到引擎的分水岭）
**范围**：
- 正则字面量 + 最小正则引擎（或桥接 `re` 模块，接口对齐 JS 语义）
- `for...of` + 迭代器协议（`Symbol.iterator` 玩具、生成器 `function*` / `yield`）
- `Date` / `Math` 完整化、`JSON` 全项、`String`/`Array` 剩余方法清尾
- **标记-清除 GC**（当前估计是引用计数或不回收，需确认现状）
- **AST 与执行分离**：解释器重构为 Parser → AST → Evaluator 三段，为未来优化/DevTools 铺路
**测试清单方向**：正则 6 条、迭代器/生成器 6 条、GC 用弱引用验证回收 3 条、AST 纯度 2 条、语法清尾 3 条。
**测试目标**：585 → 605
---
### P30：DOM API 补全（M3 收官）
**范围**：
- `querySelector` / `querySelectorAll` 全选择器支持（复用 CSS 选择器引擎）
- 节点增删改：`appendChild` / `removeChild` / `insertBefore` / `replaceChild` → **触发失效重绘**（接现有失效体系）
- `classList` / `setAttribute` 全套 / `dataset`
- `createElement` 动态构建 DOM
- 自定义事件：`addEventListener` 任意事件名 + `dispatchEvent`
- **M3 里程碑重构窗口**：DOM/渲染二段式管线确认——JS 修改 DOM 后到下一帧的更新路径统一
**验收（M3 总检收）**：浏览 2–3 个手选简单真实站点（纯文风博客、文档页），排版可读、链接可点击跳转、后退可用、表单可提交搜索。
**测试目标**：605 → 625
---
## 4. 阶段组 D：浏览器外壳（P31–P32）→ 里程碑 M4
### P31：GUI 外壳
**范围**：
- 选型：tkinter（零依赖）或 SDL/Pyglet（性能好）；建议 tkinter 起步
- 界面元素：地址栏、前进/后退/刷新按钮、状态栏、加载进度条（接 P23 进度事件）
- 像素画布嵌入现有渲染输出
- **多标签页**：每标签独立的加载管线实例（架构上先做好页面实例隔离）
- 键盘快捷键：Ctrl+L 聚焦地址栏、Ctrl+T 新标签
**测试目标**：625 → 645（GUI 逻辑以 headless 可测部分为主，渲染快照测试）
---
### P32：会话、历史与工具（M4 收官）
**范围**：
- 历史记录：会话内 back/forward 栈 + 持久化历史文件
- 书签：增删 + `bookmarks:` 页面渲染
- Cookie 玩具：`Set-Cookie` 存储 + 请求回带（不做安全边界）
- 迷你 DevTools：`--devtools` 模式打印 DOM 树 + 任意节点的 computed style + 选择器命中来源
- 统一错误页：DNS 失败 / 连接拒绝 / 超时 / 非法 URL 各有文案
- `about:blank`、`view-source:` 玩具
- **M4 里程碑重构窗口**：全局架构文档化——写一份 `ARCHITECTURE.md` 描述模块边界
**验收（M4 总检收）**：一个普通用户能用它完成“打开浏览器 → 输入网址 → 阅读 → 加书签 → 关闭再打开历史还在”的完整流程。
**测试目标**：645 → 665

## 5. M5（可选）：深而窄方向（P33+）
M4 之后**不建议**继续横向追赶 Chrome，从以下方向选一条做深：
| 方向 | 内容 | 适合人群 |
|---|---|---|
| **A. 性能** | 增量重排/重绘（失效树化）、渲染缓存、大页面基准测试（目标：1000 节点页面布局 < 100ms） | 想学渲染引擎优化 |
| **B. 手写网络栈** | 用裸 socket 实现 TCP → HTTP/1.1 → 静态 TLS（RSA/AES 玩家版），替换标准库 | 想学网络协议 |
| **C. JS 引擎提速** | 字节码编译 + 栈式 VM 替换树遍历解释器，目标 10× 提速 | 想学语言实现 |
| **D. 安全模型** | 同源策略、CSP 头解析、URL 白名单、JS 沙箱边界 | 想学浏览器安全 |
| **E. CSS Grid 真实现** | 完整 grid 布局算法（当初 P17 候选的“深做版”） | 想学布局算法 |

## 6. 依赖关系与风险图
```
P17 字体解析
  └→ P18 行盒 ──→ P19 断行 ──→ P20 光栅化 ═╗
                                          ║ M1
P21 URL/HTTP ─→ P22 深化 ─→ P23 TLS/缓存 ─┼→ P24 HTML5容错 ═╗
                                          ║                ║ M2
        ┌─────────────────────────────────╝                ║
        ▼                                                  ║
P25 层叠 ─→ P26 块级 ─→ P27 Flex ─→ P28 表单 ─┐            ║
                                             ├→ P30 DOM ══╣ M3
P29 JS引擎/GC/AST ───────────────────────────┘            ║
                                                           ║
P31 GUI ←─（依赖 M2 网络成熟 + M3 交互闭环）─→ P32 会话 ══╝ M4
```
**主要风险**：
| 风险 | 影响阶段 | 缓解 |
|---|---|---|
| `glyf` 轮廓解析工作量超预期 | P17/P20 | 允许 P17 先用 `fontTools` 全托管，P20 再手写光栅化 |
| HTML5 容错解析范围失控 | P24 | 严格执行“简化子集”清单，adoption agency 只做 `<b><i>` 双层嵌套级别 |
| Flexbox 完整算法复杂 | P27 | 先做 `row` 单轴全项，`column`/`wrap` 作为该阶段后半目标 |
| 现有 345 测试因解析器替换回归失败 | P24 | P24 第一周只做“新旧解析器输出 diff 对比”工具，再切换 |
| GC 重构破坏解释器稳定性 | P29 | GC 做成开关（`--gc=on/off`），默认先 off 跑回归 |
