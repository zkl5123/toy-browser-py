## 三、JS 语义对照（29 例，双端执行）

方法：29 个覆盖常见 JS 语法的探针脚本，经 `new Function(code)` 在 Edge 中执行并捕获 `console.log`；同时用 toy-browser 的 `js.Host` + DOM 绑定执行同一脚本，逐条比对状态与日志。

**完全一致（状态 + 日志全同）：12 / 29（41.4%）**。

| 类别 | 结果 |
|---|---|
| ✅ 完全一致 | 基础算术、字符串转义、箭头函数、class 继承、模板字符串、try/catch/finally、错误对象（NaN/Infinity 渲染）、解构、展开运算符、for-of/setTimeout 时序、生成器、字符串方法 |
| ❌ 输出值偏差 | 三元/`typeof`/`null` 的 `undefined` 渲染（toy 输出 `"undefined"` 文本但类型映射错）、`Boolean` 拼写（`True` vs `true`）、`Array.at` 越界（`null` vs `undefined`）、`Number.parseFloat` 返回 `null` vs 数值、Promise `.then` 链日志丢失、`document.body.innerText` 缺失（toy 输出 `null` vs 完整文本）、事件点击计数（toy `final: 0` vs Edge `final: 2`——onclick 处理器未触发）、`new Date(6 参数)` 不支持（`Host._date_obj` 仅接受 0/1 参数）、`1e100` 指数字面量解析失败（`unexpected token 'e100'`）、带标签循环 `outer:` 不支持、`arguments`/默认参数渲染为 `None` |
| ❌ 一方崩溃 | `Object.values` + `JSON.parse` 嵌套（Edge 侧 `new Function` 因 `parseInt` 等触发，toy 侧通过但日志少一条） |

**核心缺陷清单（真实浏览器绝不如此）：**
1. **`undefined` 值格式化为字符串字面量 `"undefined"`**，而 toy 内部把 `undefined` 与 `null` 混用（`Array.at` 越界、`Number.parseFloat('abc')` 返回 `null` 而非 `NaN`）。
2. **布尔值渲染为 Python 风格 `True`/`False`**（应为 `true`/`false`）。
3. **`new Date(year, month, day, h, m, s)` 6 参数构造不支持**，仅 0/1 参数——真实网页日期 API 大面积失效。
4. **`onclick` 事件计数不生效**：`this.style.display` 与事件计数逻辑在 toy DOM 绑定下未真正执行 handler 体。
5. **科学计数法字面量 `1e100` 词法分析失败**。
6. **带标签的语句/循环不支持**（`label: while(...)`）。

> 注：上一轮 GLM 报告判定"三元、`typeof` 在二元式、孤立分号"会导致整脚本静默失败——本轮实测**已不再整脚本失败**（toy 引擎改为语句级容错），但相应语义仍输出错误值。

## 四、布局几何对照（7 例，`getBoundingClientRect` vs toy box 树）

方法：同一 HTML 探针（含 `box-sizing:border-box` reset、flex、grid、table、absolute、margin collapse、text wrap）在 Edge 中取 `getBoundingClientRect`，在 toy 中经 `css.apply` → `layout.layout` 取 `LayoutBox.rect`。

| 用例 | 元素 | Edge (x,y,w,h) | toy (x,y,w,h) | 判定 |
|---|---|---|---|---|
| layout_blocks | `#a`（200×50, margin 10, border 2, padding 5, box-sizing:border-box） | (18, 10, 200, 50) | **(23, 5, 190, 50)** | ❌ x 偏移 +5（border-box 宽度计算差）、y 偏 -5（margin 未正确计入 body padding 8px） |
| layout_blocks | `#b` | (8, 80, 100, 40) | (8, 80, 100, 40) | ✅ |
| margin_collapse | `#t` / `#b`（相邻兄弟 30px/10px 应塌成 30） | y=0 / y=60 | y=0 / y=60 | ✅ **已修复**（上一轮为 0 塌陷错误） |
| flex | `#row` 300×60, justify/align center，子 80×30 margin 4 | 子 (22,15,80,30) | 子 (0, 20.4, **100**, 19.2) | ❌ 子项宽度被拉伸（flex-grow 缺省误用 + 未读显式 80×30）、高度取文本行高而非 30、未居中（x=0 vs 22） |
| grid | `#g` 300×120，2 行 3 列 1fr | `#g` h=120，`#g1` (0,0,100,**60**) | `#g` h=**38.4**，`#g1` h=19.2 | ❌ 行轨道未等分容器高度（toy 按文本行高 19.2 而非 60） |
| table | `#tab` 2×2，td padding 4 | w=70.42（内容自适应） | w=**800**（撑满容器） | ❌ 表格列宽不收缩到内容 |
| abs | `#p` relative 200×100，`#c` absolute left30 top20 50×40 | (30,20,50,40) | (30,20,50,40) | ✅ 完全一致 |
| text_wrap | `#w` 150×120 overflow hidden | (0,0,150,120) | (0,0,150,120) | ✅ |

**结论**：绝对定位、边距塌陷、块级基本几何已对齐；**系统性偏差集中在 flex 子项尺寸/对齐、grid 行轨道高度、table 列宽自适应**——这三类在真实网页中使用频率极高，是布局层面当前最主要的失真来源。

## 十、修复建议（按优先级）

1. **P0 — JS 输出格式化统一**（`toy_browser/scripting/js.py` 的 `_jsnum` / console.log 渲染层）：`Boolean` → `true/false`、`undefined` 与 `null` 区分、`Number.parseFloat` 失败返回 `NaN`、`Array.at` 越界返回 `undefined`。成本最低、收益最大（直接提升 §3 一致率）。
2. **P0 — 补齐高频 JS 构造**：`new Date(6 参数)`、科学计数法字面量、标签循环/语句、`onclick` 事件 handler 体真正执行（当前计数为 0）。
3. **P1 — 布局三大系统偏差**：flex 子项读显式 width/height 且 justify/align 居中生效；grid 行轨道按容器高度等分而非文本行高；table 列宽自适应内容。
4. **P1 — 清理静态风险**：`toy_browser/network/net.py:631` 函数体内惰性引用 `cookie_store` 未定义名（真实 `NameError` 隐患，改显式 import 或模块顶导入）；`toy_browser/app/gui.py:428` / `toy_browser/app/browser.py:56` 字符串注解加 noqa 或确认 `annotations` future 生效；22 处 `BLE001` 盲 except 收窄、删除 4 处 `F811` 死代码重定义。
5. **P2 — 性能**：纯 Python CPU 光栅化 2 个数量级差距是架构固有；若需接近可用，建议走 C 扩展（CFFI/numpy）光栅化或增量失效树，短期可先补 `changed_region` 驱动的局部重绘。
