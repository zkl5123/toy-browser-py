# toy-browser-py 逐项改进实施方案

日期：2026 年 10 月 16 日。依据第五轮实测，对提交 `956220e` 展开实施建议。本文覆盖浏览器功能、GUI、CPU 性能、GPU 后端与回归体系；它是实施规格，不表示以下改动已经完成。

实测基线：完整回归 939/939；51 个 JS 案例规范化日志后相符；48 个边框盒探针对齐；CLI 与 GUI 的 10 个 HTTP 任务均通过。剩余主要问题包括 GUI 滚动条与 Enter 激活、事件循环阻塞、图像呈现转换耗时、行内排版，以及复杂绘制的一致性。

第五轮 5000 元素代表样本中，布局约 3319ms、显示列表构建约 1336ms、光栅化约 151ms；GUI PhotoImage 转换中位约 1209ms。这决定了先修 GUI 与 CPU 热点、并行建立可选 GPU 后端的顺序。全部性能数字见原始报告，本文的目标值均为建议验收门槛。

## G01 滚动条协议与范围

**问题与位置**：`toy_browser/app/gui.py` 的 `TabBrowser._ensure_page_frame` 使用 movements/units 分支，Tk 实际调用 moveto 或 scroll；`_refresh_canvas` 的拇指起止比例也不正确。实测拖动后偏移仍为 0。

**实施步骤**：

1. 将匿名 `_sb` 提取为可独立测试的 `handle_scroll_command(tab_id, operation, *args)`。
2. moveto 接收 fraction，按总内容高度定位；scroll 接收有正负号的 count 及 units/pages，分别按可配置行步长和约 90% 视口高度移动。
3. 统一调用 PageInstance.scroll_to，由它处理 0 到 scroll_max 的边界；内容更新或视口变化后再次夹紧。
4. `_refresh_canvas` 设置 first=offset/content_height，last=(offset+viewport_height)/content_height。内容不溢出时设为 0、1，避免除零。
5. 拖动只提交滚动请求，不触发样式或布局；合并同一帧内的多次移动。

建议规则：

```text
moveto f        -> clamp(f * content_height, 0, scroll_max)
scroll n units  -> scroll_by(n * line_step)
scroll n pages  -> scroll_by(n * viewport_height * 0.9)
```

**测试与验收**：新增 `tests/test_gui_scroll.py`，覆盖空页、短页、2000px 长页、moveto 0/0.5/1、正负 units/pages、内容缩短与窗口放大。测试实际 Tcl command，而非仅调用 scroll_to。拖到末尾 last=1；向上操作必须减小 offset；静态滚动不增加布局调用次数。

**交付**：处理函数、范围公式、协议测试、实测脚本更新。参考 [Tk 官方 scrollbar 协议](https://web.tcl.tk/man/tcl8.7/TkCmd/scrollbar.html)。

## G02 鼠标与键盘统一激活

**问题与位置**：`toy_browser/app/gui.py` 的 `_click_dispatch` 已能执行 onclick，`_activate_focused` 仍主要处理控件状态，实测 Enter 未把 SAFE 改为 CLICKED。

**实施步骤**：

1. 建议新增 `activate_element(node_id, source)`，集中处理脚本 click 事件与控件默认动作；两个 GUI 入口只负责确定目标。
2. 先派发可取消事件，再决定是否执行默认动作。preventDefault 后不提交表单、不跟随链接；不要由两个入口各调用一次 onclick。
3. button 的 Enter 激活，Space 按下时进入按压状态、松开时激活；checkbox/radio 的 Space、链接的 Enter 分别按控件语义处理。
4. 输入框 Enter 的隐式表单提交单独处理；textarea Enter 插入换行。不要让任意 input 的 Enter 都等价于鼠标点击。
5. DOM 回调完成后排空应执行的微任务，更新控件状态和 damage，再请求呈现，保留当前 Document。

**测试与验收**：对照 Edge 记录 click 次数、checked、导航和 submit。覆盖鼠标、Enter、Space、disabled、preventDefault、脚本删除目标节点。一次动作只能触发一次激活；表单取消后不得发请求。

**交付**：共享激活入口、默认动作表、`tests/test_gui_activation.py`，以及与 Edge 相同 HTML 的事件日志。

## G03 编辑 选区与输入法

**目标与位置**：补全 `toy_browser/app/gui.py` 的 active_form_field、`_set_form_value` 与编辑控件之间的连接，替代“有焦点但不能完整编辑”的状态。

**实施步骤**：

1. 建议引入 `EditorState`：node_id、value、selection_start/end、caret、composition_range、undo/redo、dirty 标记。
2. Tk 过渡版给活动 input/textarea 放置原生 Entry/Text 覆盖层，位置来自布局与视口转换。滚动、缩放、失焦或节点销毁时同步或撤销覆盖层。
3. 普通编辑执行 beforeinput、更新 value、input；取消的 beforeinput 不修改值。change 在适当提交/失焦时触发，不为每个按键重复触发。
4. 接通左右/Home/End、删除、选择、复制粘贴、撤销和密码输入。password 的显示与剪贴板策略明确分离，不能把遮罩字符写回 DOM value。
5. IME 使用原生组合输入能力，区分组合区更新和最终提交，维护 composition 与 isComposing 语义；以实际 Edge 与系统 IME 日志确定事件顺序。
6. DOM value 由脚本改变时，按控件是否处于编辑状态同步，保留可解释的选区位置，避免下一次重绘还原成 HTML 初始 value。

**测试与验收**：英文、中文拼音组合、粘贴含换行文本、选区替换、密码、disabled/readOnly、脚本改值、失焦后重绘。程序测试编辑状态；另做真实键盘与 IME 人工验收，不能以设置字符串代替输入法测试。

**交付**：EditorState、原生覆盖层适配、input/textarea 事件测试及 IME 验收记录。

## G04 焦点和输入路由

**目标与位置**：调整 `TabBrowser` 的 root.bind、地址栏绑定和 PageInstance.focus_next，使地址栏、页面和编辑器互不误触发。

**实施步骤**：

1. 建议新增 `FocusManager`，分清 chrome、document、editor、dialog 四种归属，保留页面最后焦点。
2. 用稳定 node_id 表示焦点，不长期依赖 DOM 遍历下标；删除、隐藏、禁用节点时重新确定焦点。
3. 快捷键按归属处理：地址栏 Return 仅导航，编辑器处理文本命令，页面才接收页面激活。已消费的事件终止继续冒泡。
4. Tab 顺序复用 `browser.tab_order`，过滤不可聚焦元素，处理正 tabindex 与 tabindex=-1；区分键盘焦点提示与鼠标焦点。
5. 模态对话框开启时限制焦点范围，关闭后恢复此前焦点。

**测试与验收**：地址栏 Return 不点击页面按钮；Tab/Shift+Tab 顺序与 Edge 相符；节点删除后焦点不会指向错误元素；切标签后恢复对应文档焦点。

**交付**：路由表、稳定节点引用和 `tests/test_focus_routing.py`。

## G05 滚轮与触控板

**问题与位置**：滚轮绑定在 viewport Frame，像素显示在 Label；不能假定子控件事件自动经过父 Frame 的绑定。

**实施步骤**：

1. 在实际显示控件或统一的页面 bindtag 上接收滚轮事件，限定为当前视口，不使用影响对话框和工具栏的无条件全局绑定。
2. 转换为统一 `WheelInput(dx,dy,units,modifiers)`，累计 Windows 小 delta，delta=0 不移动；处理横向/Shift 与不同平台单位。
3. 命中可滚动子容器时优先滚它，到边界后再按规则链到外层页面。
4. 合并同一帧输入，只请求一次合成或裁剪呈现。

**测试与验收**：指针在文字、空白和控件上都能滚动；四个小 delta 不被全部丢弃；横向滚动与嵌套容器不误滚整个页面。程序检查绑定与累积算法，物理触控板单独验收。

**交付**：统一滚轮输入、累计器、嵌套滚动测试。

## G06 动态视口 DPI 与页面缩放

**问题与位置**：导航固定传 800×600，未用内容区 Configure 驱动重排。

**实施步骤**：

1. 监听页面内容控件实际尺寸，扣除 chrome；合并连续 resize，约 16–50ms 提交一次最新尺寸。
2. 建议新增 `ViewportState(css_width,css_height,ui_width,ui_height,device_scale,page_zoom,scroll_x,scroll_y)`，避免散落比例计算。
3. 布局使用 CSS 像素；GPU/图像使用物理像素。UI 逻辑事件到 CSS 坐标为 `(position-content_origin)/page_zoom+scroll_offset`；只有物理事件坐标才先转换成逻辑坐标。
4. 改变尺寸或 zoom 后重排，夹紧滚动位置，更新原生编辑覆盖层、命中树与 scrollbar。
5. DPI 变化时使对应 glyph/texture 尺寸缓存失效，不清除无关文档状态。

**测试与验收**：DPR 1/1.25/1.5/2、缩放 90%/100%/125%、窄窗宽窗、跨屏 DPI 变化。文字换行、点击目标、输入光标和滚动范围使用同一变换；连续 resize 不显示旧版本帧。

**交付**：ViewportState、统一坐标转换、resize 合并器和参数化测试。

## G07 UI 与文档工作分离

**证据与位置**：`_navigate` 同步调用 load_url、布局和 `_refresh_canvas`；本轮 1ms Tk 定时器约 1527ms 后才能执行。

**实施步骤**：

1. 建议新增 DocumentController，UI 只投递 Navigate/Input/Resize/Scroll/Stop 命令，持有有限状态镜像。
2. DOM、JS Host、布局树由一个串行文档工作单元拥有。网络工作池只返回响应，不直接在网络线程修改 DOM。
3. Tk 控件与 PhotoImage 保留在主线程，通过 after 或队列取回工作结果。初版可先移出网络 I/O，再逐步移出 CPU 工作。
4. 纯 Python CPU 工作不能期待普通线程带来多核加速；评估文档进程方案，使 DOM 长期留在该进程，仅传紧凑命令与帧。不要每帧序列化整棵 DOM。
5. 队列有界，旧 resize/scroll 合并，呈现只保留最新有效帧。保留现有 JS 预算与超时约束。
6. 所有结果携带 C01 的文档与帧版本；收到已关闭标签或过期导航的结果立即丢弃。

**测试与验收**：受控慢服务器、CPU 长布局、快速 A→B 导航、停止和关标签。加载期间地址栏与标签切换仍响应；A 的结果不覆盖 B；UI 不调用阻塞网络函数。建议足够样本下 UI 调度 p95<50ms，不是当前已达成结果。

**交付**：控制器、有界 IPC/队列、事件追踪与取消回归。此项先完成边界，再逐步替换执行位置。

## G08 导航状态 停止与错误

**位置**：`toy_browser/app/gui.py`、`toy_browser/network/net.py`、`browser.render_document_from_url`。

**实施步骤**：

1. 建立 idle/loading/interactive/complete/failed/cancelled 状态，记录当前 URL、最终 URL、主文档与资源进度。
2. UI 立即显示 loading，刷新按钮变停止；完成、失败和取消分别更新状态，不统一写成 Loaded。
3. Stop 先逻辑取消并回复 UI，再请求可取消 transport 关闭/超时；不强杀 Python 工作线程。
4. 错误页区分 DNS、TLS、超时、HTTP 与脚本错误；给重试入口，控制台保留原始错误。
5. 缓存命中、跳转和失败不得把地址栏正在编辑的文字意外覆盖；失焦/导航提交后再同步最终 URL。

**测试与验收**：慢响应、重定向、404、TLS 错误、取消、取消后重试。Stop 可立即反馈，过期完成事件无效，进度只代表实际可知阶段。

**交付**：状态机、UI 状态映射与导航故障夹具。

## G09 标签页与历史会话

**位置**：TabBrowser 的 `_add_tab/_remove_tab/_show_tab`、PageInstance 历史栈、`toy_browser/app/session.py`。

**实施步骤**：

1. 标签使用稳定 tab_id，不把列表位置作为长期身份；关闭中间标签后重建映射，旧回调不能操作其他标签。
2. 每标签维护 DocumentController、历史、滚动、焦点和加载任务；切换只改变前台呈现，不重建文档。
3. 统一地址栏、链接、书签和文件打开的历史提交路径，明确重定向只形成哪一个历史项。
4. 后台标签减少重绘，定时器策略单独定义；关闭标签取消任务并释放 CPU/GPU 资源。
5. 会话持久化仅保存可恢复状态，使用 toy_browser/app/session.py 的原子写入；损坏文件可降级打开。

**测试与验收**：至少三标签、关闭首/中/末标签、后台加载完成、历史前后、书签跳转和恢复损坏数据。不串页、不重复历史项、不泄漏已关闭标签任务。

**交付**：稳定标签身份、统一导航历史入口、会话回归。

## G10 工具栏 状态栏与诊断区

**实施步骤**：

1. 顶部采用标签栏、导航栏、内容视口结构；后退/前进按历史栈启停，刷新/停止随 G08 状态切换。
2. 标题使用文档 title，加载前可临时显示 URL；关闭、新建和菜单提供快捷键与工具提示。
3. 状态栏显示悬停链接目标、真实加载阶段与失败摘要；不要以 HTTPS 图标代替页面整体安全结论。
4. Console/Network/DOM/渲染计时放可展开诊断区，普通使用不堆放内核实现信息。
5. 诊断记录 document_id、backend、各阶段时间、缓存与 fallback 原因；提供导出诊断信息按钮。

**测试与验收**：不同加载状态按钮一致；窄窗地址栏仍可用；标题和状态不被后台标签覆盖；关闭诊断区不改变页面行为。

**交付**：布局规格、状态映射、诊断面板与交互截图。

## G11 可访问性与键盘全流程

**位置**：GUI 控件、`browser.collect_accessibility_tree` 和 focus/tab_order。

**实施步骤**：

1. 原生工具栏保留角色、名称、快捷键和可见焦点环；页面像素 Label 不能被视作已提供完整页面可访问性。
2. 复用已有 a11y 树作为语义源，评估向 Windows/Qt 可访问性接口桥接；未桥接前明确标注限制。
3. 建立无需鼠标的任务：输入地址、导航、Tab 到表单、编辑、提交、后退与关标签。
4. 页面焦点滚入可见区域，避免控件虽然聚焦但仍在屏幕外。

**测试与验收**：自动核对语义与焦点树，人工用实际读屏器和键盘完成任务；不以 JSON 树存在代替读屏可用。

**交付**：语义映射表、键盘任务清单、读屏验收记录。

## C01 Document 生命周期与任务版本

**目标**：避免重排重新执行脚本、HTTP 文档被源 HTML 覆盖及异步结果串页。这些基础路径本轮已通过，应通过架构约束保住。

**实施步骤**：

1. 建议抽取 DocumentState，拥有 DOM、Host、DocumentPolicy、资源、样式/布局版本和稳定 node_id。
2. 解析和脚本初始化属于新文档加载；hover/focus/scroll/resize 只能使相应阶段失效，不重新创建 Host。
3. 区分 document_id、navigation_epoch、layout_revision、frame_id；每类结果明确携带版本。
4. 建立 DocumentController 的唯一修改入口，把 GUI、CLI 和测试都接到同一流程，保留公共 API 包装层兼容旧调用。
5. 新导航先创建新上下文，旧上下文待任务与帧资源释放后销毁，不能跨源复用策略或 JS 全局。

**测试与验收**：脚本初始化计数只增加一次；重排后点击监听仍在；异步 A 文档结果不写入 B；CLI/GUI 相同输入得到同一 DOM。

## C02 连续像素缓冲区及 GUI 呈现

**证据与位置**：`paint.Bitmap` 使用 int 列表；`_bitmap_to_photopix` 逐像素打包 PPM，转换链约 1209ms。

**实施步骤**：

3. RGB/RGBA/BGRA、机器端序和每行 padding 明确区分。Tk 需要的 RGB 通过批量转换获得，不在 Python 中对每像素创建临时 bytes。

**测试与验收**：随机像素、不同 stride、奇数宽度、透明图片和小图逐像素一致；兼容现有 CLI。建议先争取 800×600 转换链比本轮下降 80%以上，再追求帧预算；目标需实际测量确认。

**交付**：CPUImage、适配层、缓冲池、颜色格式与生命周期测试。

## C06 布局树构建与增量布局

## P07 裁剪 变换与透明组

**实施步骤**：

1. 矩形裁剪用 scissor；复杂圆角/嵌套裁剪使用 mask 或 stencil，并明确坐标转换和嵌套上限。
2. transform 保留矩阵栈，计算保守绘制 bounds；输入命中使用同一变换的逆变换。
3. 组透明度先把组内图元画到隔离层，再统一混合；不能把组 opacity 分别乘到每个子项替代。
4. 暂不支持的组合可在完整隔离层边界 CPU 回退，保留 alpha 和顺序，缓存回退结果。

**测试与验收**：两个重叠子项的组透明度、嵌套裁剪、旋转缩放、越界命中、CPU 回退与 GPU 混合。无漏画、错误叠加和点击偏移。

**交付**：clip/layer/transform IR、离屏层池与混合测试。

## P08 阴影与滤镜

**实施步骤**：

1. 将现有 shadow/text_shadow/filter 变为独立效果任务，先确定输入图层、核大小和输出 bounds。
2. 模糊采用横向、纵向分离 pass，复用临时纹理；核截断范围与 CPU 参考一致。
3. 先覆盖基础 blur、brightness、contrast，明确执行顺序；不把多个滤镜交换次序。
4. 静态阴影按内容和效果参数缓存；平移可只改变合成坐标，不每帧重新模糊。
5. 高成本大半径效果受内存与帧预算限制，可降低质量或 CPU 回退，诊断区显示实际路径。

**测试与验收**：透明边缘、裁剪附近的阴影、不同半径、连续更新和多滤镜；无边缘截断、光晕或次序错误。分别测效果 GPU 时间及中间纹理占用。

**交付**：效果 pass、scratch 池、参数缓存和滤镜金图。

## P09 GPU tile 与增量合成

**实施步骤**：

1. 初版采用可配置 512×512 物理像素 tile，键包含 document/layout/paint revision、DPR 与 tile 坐标。
2. 只绘制视口和少量预取，内容总高度保持逻辑值；不创建整页等高 GPU texture。
3. 滚动复用 tile，更新合成位移；新暴露区域加入绘制队列，前台可见 tile 优先。
4. C08 的 damage 转换为受影响 tile，包含效果扩展边界；禁止每帧读回后再比较像素决定失效。
5. 采用有限在途帧与预算淘汰；快速滚动先显示已有 tile，取消过期预取，不能让旧文档 tile 串入新页。

**测试与验收**：超长页面、快速来回滚动、字体改变、图像加载、缩放、窗口 resize。内存随缓存预算而非文档总高度增长；热缓存静态滚动不重做全页布局和绘制。

**交付**：tile 调度、版本化缓存、damage 映射与滚动追踪。

## P10 预算 释放与设备恢复

**实施步骤**：

1. 统一记账纹理、atlas、tile、实例 buffer、临时层和帧缓冲；使用明确总预算，不把 WMI AdapterRAM 当可用显存。
2. 可从 128MiB 资源缓存和可配置总预算开始试验；帧缓冲与临时层必须计入总量，尺寸变化前预估需求。
3. 按最近使用帧与引用淘汰；GPU 尚在使用的资源延后释放，文档关闭也要等待安全回收点。
4. 初始化、提交、分配和 surface 错误统一进入恢复状态：丢弃失效 GPU 句柄，重新获取设备并重建可恢复资源，或切换 CPU。
5. 恢复期间 UI 保持可操作，不无限自动重试，不反复累积旧资源。

**测试与验收**：低预算、多标签开关、连续 resize、模拟设备错误和 adapter 不可用。资源回到预算内，页面可恢复或明确回退，不留下悬挂帧。

**交付**：资源账本、延迟回收、恢复状态机及故障注入测试。

## P11 色彩 alpha 与像素一致性

**实施步骤**：

1. 在 contracts 中写明图像通道、色空间、alpha 模式和最终 surface 格式。首版不透明窗口减少透明窗口平台差异。
2. 中间层采用明确的预乘 alpha；glyph coverage、图片 alpha、组 opacity 不能重复相乘。
3. 当前 CPU 在编码后的 RGB 上做近似混合。首版建立兼容基线，显式处理最终 sRGB 编码，避免硬件再次编码造成变亮。
4. 若迁向线性空间混合，作为独立行为变更，同时修改 CPU 参考与版本化金图，不能混入性能改动后笼统放宽容差。
5. 几何边界、实色内部、文本抗锯齿分别统计差异；文字不要求跨字体实现字节完全一致，但基线和占位必须一致。

**测试与验收**：半透明红蓝重叠、透明图片边缘、渐变、文字 coverage、灰阶、不同 surface 格式。无黑边、双重 gamma 和重复透明度。

**交付**：颜色约定、CPU/GPU 转换函数、分类型像素误差报告。

## P12 GPU 性能与正确性验收

**实施步骤**：

1. 固定输入、窗口、DPR、驱动、backend 与 CPU/GPU 模式，分别记录冷启动和热缓存。
2. 负载至少包括当前长页面、绘制重页面、真实 GUI 操作。绘制重页要有图像、阴影、圆角和透明组，不能只测屏外节点。
3. 分测 CPU 准备、实例打包、上传、GPU 执行、present 等待和截图回读。GPU 提交返回时间不等于 GPU 完成时间。
4. 设备支持时使用时间戳查询；不支持时记录能力限制，以完整帧和队列完成数据辅助判断。
5. 先与 CPU 后端比较同一 Scene 的正确性，再与 Edge 比较产品行为；CPU 参考本身的排版错误不能被称为 GPU 正确性的最终标准。

**测试与验收**：足够样本后报告 p50/p95 和离群值；建议目标为热缓存滚动 p95 接近 16.7ms、UI 调度 p95<50ms。目标未达成时如实记录，不用 shader 微基准代替整端响应。

**交付**：可重放 Scene、GPU-heavy 基准、CPU/GPU/Edge 三方报告和帧时间追踪。

## P13 可选依赖 打包与 CPU 回退

**实施步骤**：

1. CPU 入口保持无第三方依赖；可选 GPU 包记录 wgpu/rendercanvas/PySide6 的固定版本及原生运行库。
2. 在创建后端前明确选择 cpu/auto/gpu。auto 失败回退；显式 gpu 失败给可诊断错误，并允许用户改用 CPU。
3. 发布时验证原生 DLL、字体、shader 和资源路径；不依赖开发机器的绝对缓存目录。
4. 提供诊断导出：硬件、驱动、后端、功能限制、颜色模式、资源预算与错误。
5. CPU 与 GPU 共用文件和会话格式，GPU 不可用时仍能打开页面、保存截图和跑离线回归。

**测试与验收**：干净环境只装 CPU、装 GPU、缺 DLL、离线、软件适配器和无权限环境。既有 CLI 命令保持可用，安装 GPU 包不改变默认行为。

**交付**：依赖锁定、安装说明、打包脚本与干净环境测试。

## Q01 标准对照与功能任务回归

**实施步骤**：

1. 把第五轮输入和期望冻结为带版本的测试资产，记录 Edge 版本、视口、DPR、源码提交与容差，旧评估文件不再被后续运行覆盖。
2. 离线测试覆盖快速语义与像素；本机 HTTP 覆盖真实传输和策略；GUI 测试必须通过实际操作入口。
3. 将“API 存在”“最小回调”“完整页面任务”分级统计。双方都因无效输入报错的案例不能计作正向功能支持。
4. 异步测试保存 console、page error、drain_error、超时和最终 DOM，不吞异常。
5. 先引入相关 WPT 模块子集，建立 expected failure 清单；修复一个删除一个，不把失败预期改成当前实现值。

**测试与验收**：每项交付附最小复现、修复前失败、修复后通过以及未覆盖范围。CLI/GUI 两入口都验证，像素与几何分开统计。

**交付**：测试资产目录、不可变运行记录、模块能力矩阵和 CI 任务。

## Q02 性能追踪 内存与发布门槛

**实施步骤**：

1. 为 Document 任务、布局、显示列表、光栅化、呈现和导出统一 trace_id，记录时间、数量和缓存命中。
2. 每次样本保存完整阶段向量，整端中位数不能用不同样本的阶段最小值相加伪造。
3. 记录进程 RSS/提交量与 GPU 自有资源账本，明确平台 API 不可用时标为未知，不能把 0 当有效结果。
4. 设置正确性先行的发布门槛：无新增策略违规、无状态串页、已通过回归不退化；性能在固定环境多轮判断。
5. 每次发布保留 CPU 稳定路径，GPU 先实验标记，满足 P12 和故障恢复后再推荐。

**测试与验收**：同一场景多轮、冷热缓存、前后台、多标签和失败路径。报告实际 p50/p95、样本数和硬件，不承诺未经测得的加速倍数。

**交付**：统一 trace、性能看板数据、内存记录与发布检查结果。

## 实施批次与退出条件

| 批次 | 工作范围 | 必须满足后才进入下一批 |
|---|---|---|
| 1 基本操作 | G01/G02/G04/G05，C01 骨架 | 滚动、鼠标/键盘激活和稳定身份测试通过 |
| 2 编辑与响应 | G03/G06/G07/G08/G09，C02 | 可输入、可取消、不串页，显示转换显著下降 |
| 3 视觉正确性 | C03/C04、G11 | 基础文本可读、表单任务完整，真实键盘验收通过 |
| 4 CPU 与回归 | C05–C10、Q01/Q02 | 同结果下减少布局/命令构建，增量与全量一致 |
| 5 GPU 基础 | P01/P02/P03/P11/P13 | 后端可选、直接呈现、颜色和回退契约明确 |
| 6 GPU 绘制 | P04–P08、P10 | 图元、文字、图片、裁剪和效果正确且资源受控 |
| 7 GPU 增量与发布 | P09/P12、G10 | 整端与绘制重负载改善，UI 与设备恢复验收通过 |

批次表示依赖顺序，不是未经估算的工期承诺。C03 的视觉修复与 GPU 基础接口可以在契约冻结后独立推进，但不能带着不一致的排版、颜色与资源所有权进入集成。

建议每个工作项交付一个可独立审查的变更，说明模块、行为、验证及剩余限制；涉及数据格式时保留兼容适配。每批结束更新能力矩阵，而不是只增加功能名。
