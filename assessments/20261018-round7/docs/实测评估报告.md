# toy-browser-py 第七轮：按真实浏览器标准的系统评估

**日期**：2026-10-18　**代码基线**：`2d1bdd31c982fe6637be30da393f47f4170e2750`  
**定位**：已具有真实网络、脚本解释、HTML/CSS/布局、CPU 绘制和 GUI 外壳的实验性浏览器内核；当前尚不能作为安全、兼容、可日常使用的通用浏览器。

### 为什么 1914/1914 仍不足以证明完成

完整环境日志实际含：

```text
FAIL 3000-node pipeline not slower than P34.4 (~9.5s)  got 15.9s
FAIL 10k-node pipeline not slower than P34.4 (~29.4s)  got 46.4s
RESULT: 1914/1914 passed in 760.5s
```

相关测试内部 helper 只记录/打印失败，没有向 runner 抛异常；runner 只把“函数未抛异常”当作 PASS。另有无依赖提前 return、恒真断言、导入失败只 WARN、未知 --only 可以空集成功等问题。**这证明统计口径不可靠，不证明全部1914项都是无效测试。** 大量正常回归仍有价值，应保留并修结果契约。

性能阈值失败也不能直接解释成源码回退：本轮运行环境、Python 版本、并行审计负载不同。应在隔离稳定负载下重建基准，然后启用独立性能门禁。

## 3. 已有成果应当保留

1. HTML→DOM→样式→布局→显示列表→位图真实执行；不是纯UI原型。
2. HTTP/TLS、重定向、连接池、部分缓存与子资源加载有真实实现；不能再笼统称网络都是 stub。
3. JS 具有 parser/interpreter、作用域、Promise/timer 等基础；B03 语法异常边界在本轮探针中有效，坏脚本后续好脚本继续。
4. B05 的 location 已不是普通 dict：`replace/assign/href` 会生成导航任务，`browser.render_document_from_url` 有有界跟跳；剩余问题是跨入口接入、历史与生命周期。
5. B01 启动参数路由已有新逻辑和回归；不再沿用“所有启动URL都被丢弃”的旧结论。
6. 真实字体 TTF/TTC 解析、8-bit coverage mask、连续 CPUImage、dirty/layout 缓存等是可复用基础，不能因为 GPU 未接字体就说项目没有真实字体。
7. GPU 侧已有真实设备申请、纹理上传/读回和缓存结构；文档进程可真实 spawn。这些是基础设施成果，但不等于最终的 GPU 绘制/多核页面渲染。
8. 历史 51 JS/48 盒子样本保持结果，说明这些固定场景未在本轮重放中出现新的明显回退。

## 4. 按真实浏览器能力评估

| 维度 | 当前判断 | 主要障碍 |
|---|---|---|
| 不可信内容安全 | **发布阻断** | JS可达Python宿主、跨源响应暴露、CSP多入口缺口、分配前资源约束缺失 |
| HTML 解析 | **基础实现，不符合完整HTML解析算法** | 属性引号中的`>`、重复属性、RCDATA、空白、隐式文档/表格元素 |
| CSS 样式 | **基础正确性需优先修复** | specificity比较、结构/id选择器缓存污染、未知伪类处理 |
| 布局 | **有限场景可用** | 新增row-gap/colspan等反例失败；旧盒子全通过不足以覆盖算法 |
| 字体和文字 | **已有真实字体基础，排版链不完整** | shaping/Bidi/cluster、fallback一致性、GUI/CPU/GPU不同字体路径 |
| JS 语言 | **子集解释器，基础语义仍偏离** | true===1、UTF-16、默认sort、Number/Boolean/parseInt、属性顺序/in |
| Web API/调度 | **部分实现与占位混合** | Response读body反向reject、XHR POST→GET、timer早于microtask、存储生命周期 |
| 导航与GUI | **可运行外壳，主链尚未统一** | 默认同步、pending_nav未消费、刷新历史策略丢失、旧文档状态/命中身份 |
| 多进程 | **机制存在，默认页面计算未迁移完成** | worker回URL/版本而非完整页面，默认入口没有完整派发/呈现闭环 |
| GPU | **CPU绘制后上传验证阶段** | GPUBackend先整帧CPU rasterize，atlas透明，图片键碰撞，present占位 |
| 可访问性/输入 | **内部模型基础，不等于平台可用** | 编辑层缺原生控件接线、IME/系统辅助功能未完成认证 |
| 工程与测试 | **规模可观，质量门禁需重建** | 自测与规范同源偏差、skip/导入/内部FAIL统计、文档完成声明失真 |

## 5. 必须先处理的 P0

### 5.1 JS 与宿主对象没有可靠边界

实测页面脚本可读 `location._host.doc_url`、`localStorage.__class__.__name__`、`fetch.__self__._js_step_budget`。根源是 `js.py` 对普通 Python 对象通用 getattr/setattr/call fallback。**仅验证无害属性可达，没有尝试系统命令、文件读取或利用，因此不能称“已证明RCE”。** 但这已经足以否定当前可安全运行任意不可信脚本的假设。

### 5.2 请求策略没有覆盖真实API主链

双回环来源实验：无 ACAO 的跨源 XHR 可读合成正文；fetch 可读 status 和暴露的私有正文；`connect-src 'none'` 仍发出请求；Strict Cookie随不应携带的跨站子请求发送。

相反，正常的同源 `script-src 'self'` 脚本又被要求 ACAO，classic 跨源脚本模式被误判。不能简单“多拦一点”修复，需要按 destination/mode/credentials 建统一 Fetch 策略。

### 5.3 CSP与页面生命周期不一致

实测：CSP 禁止资源仍先请求；`<base>` 改写 self 比较来源；on*事件绕过；关闭子资源下载同时关闭inline策略；空指令/重复指令错误处理。

静态补充：GUI 刷新/历史路径丢弃响应策略再执行 `load_html`，首次加载的策略修复并未覆盖整个导航生命周期。详见安全与GUI审计的行号链。

### 5.4 资源限额发生得太晚

GET raw/gzip先完整读取/解压再检查；配置128字节时gzip/POST的4096字节合成回复仍能通过部分路径。测试仅小样本，不曾运行内存耗尽负载。应在分块读取和增量解压过程中拒绝，且GET/POST/redirect共用预算与清理。

### 5.5 测试及默认主链闭环

安全修复必须在可信测试结果和默认GUI/CLI入口上验收。只新增 Policy 类或 Worker 类而不替换默认调用点，不能解决实际使用风险。

## 6. 标准正确性的具体反例

### HTML/CSS/layout

- 引号属性值 `a>b` 实际截为 `a`；重复属性实际后者覆盖而非保留首个。
- textarea/RCDATA `&amp;` 未按预期解码，纯空白文本丢失；省略html/body和tbody的输入未构造标准隐式结构。
- `#x` 被 `.a.b` 压过；first-child/id匹配结果在相同tag/class兄弟间错误复用。
- Grid行高20、row-gap10时第二行y=40，预期30；指定表格span场景colspan=2实际宽50、预期100。

这些不是增加属性支持数量能解决的问题。CSS缓存优化正在改变语义，必须先正确，再优化。

### ECMAScript与Web API

| 输入/行为 | 标准/当轮V8 | 当前项目 |
|---|---|---|
| `true === 1` | false | true |
| `"😀".length` | 2个UTF-16码元 | 1 |
| `"😀".charCodeAt(0)` | 55357 | 128512 |
| `[2,10,1].sort().join(',')` | 1,10,2 | 1,2,10 |
| `Object.keys({'10':'a','2':'b','x':'c'})` | 2,10,x | 10,2,x |
| `Number(null)` | 0 | 内建对象字典表示 |
| `Boolean([])` / 全局parseInt | 可调用 | ReferenceError |
| Response.text() | fulfilled正文 | rejected，错误值是正文 |
| XHR open POST + send | 服务器收POST | 服务器收GET |
| 同步、Promise、timer | 微任务先于下一timer | 探针timer先于microtask |

完整输入/日志/错误见JSON。其余11项一致是实际成果，不能反过来把所有JS都评为未实现。

## 7. GUI、进程与GPU的“接线差距”

### 默认导航仍同步

`TabBrowser._commit_navigation → PageInstance.load_url` 在主线程进行网络、脚本、布局。真实spawn存在，但 `_g07_post_nav/_resize/_drain_frames` 没有形成默认调用闭环；worker handle 主要处理计数、URL和版本。需要搬运真正的DocumentSession负载，而不是继续增加消息结构。

### B05只完成了一部分入口

`browser.py:194-216` 会跟随同步脚本导航；GUI自己的首次HTTP管线执行脚本后直接绘制，没有消费 `_pending_nav`。刷新/历史也有独立路径。因此不能把API跟跳成功写成“地址栏打开脚本跳转页完整通过”。跨跳seen、默认client保持、replace历史和异步回调导航也需统一。

### 命中、about页面和关闭

静态审计发现：hit_test_at按所有节点计数，而_node_index_to_dom只按元素计数；含文本树会错位。about分支未清空旧DOM/Host/display-list，默认呈现又优先缓存显示列表；窗口关闭协议仅shutdown worker而没有destroy root。具体静态调用链与现有回归证据见GUI审计；本轮未新增这些GUI操作的独立端到端探针，真实物理输入/长时间运行也未验收。

### GPU现在不承担主要光栅计算

`gpu.py:794` CPU整帧绘制，`:812`上传RGBA，`:829/:835`才准备图片和字体缓存；`:946 present`仅判断frame不为空。

- P05：不同内容同尺寸红/蓝1×1图被当成同一资源，resident=1、uploads=1、hits=1。
- P06：捕获的16×256 atlas 16,384字节alpha全零；中文“中”和ASCII“-”回退字节相同，字体family硬编码。
- 最终CPU红蓝帧仍正确，说明截图一致**不能**证明这些GPU缓存正确，也不能证明它们参与了绘制。

应准确称“真实GPU纹理上传/读回基础”，而不是GPU shader光栅化或已获得加速。

## 8. 性能：以当前瓶颈排优先级

以下为历史CPU分段脚本在本轮受管Python的三次中位数，毫秒。它使用 `paint_engine.rasterize`，不是GUI最新CPUImage呈现主链；审计期间还有其他进程活动，100节点样本波动明显，不用于严谨跨轮性能比较。

| 节点数 | parse | style | layout | emit | raster | PNG |
|---:|---:|---:|---:|---:|---:|---:|
| 100 | 3.7 | 25.6 | 160.5 | 29.4 | 208.2 | 609.3 |
| 1000 | 120.6 | 536.6 | 1737.6 | 900.0 | 486.6 | 1593.6 |
| 5000 | 583.9 | 2934.0 | 8324.2 | 4754.4 | 526.9 | 1547.6 |

完整解析到像素中位数约563ms / 3794ms / 17112ms，阶段中位数相加不必等于总中位数。原始全部样本见 [pipeline_profile.json](../pipeline_profile.json)，热点见 [cpu_profile.txt](../cpu_profile.txt)。

可以支持的结论是：大DOM样本中布局和显示列表构建成本远大于光栅化；只迁GPU不会自动消除这些开销。不能据此宣称当前代码比第五轮慢多少倍，也不把CPU→GPU上传算成GPU加速。

后续应在稳定环境测真实默认主链、输入延迟、帧时间P95、内存、取消和长页面滚动；先修错误缓存与重复管线，再做增量布局/tile/真正GPU绘制。

## 9. 推荐实施路线

详细步骤、修改点、依赖和验收见 [逐项改进实施方案](逐项改进实施方案.md)。建议顺序：

1. **测试可信化**：导入/skip/内部FAIL/超时正确计数，去恒真断言。
2. **安全收口**：JS宿主白名单、统一RequestContext/CSP/CORS、分配前限额、Cookie上下文。
3. **页面主链统一**：DocumentSession持有状态，CLI/GUI/刷新/历史/脚本导航共用控制器，about/error原子切换。
4. **基础语义修复**：CSS specificity/缓存、JS类型/UTF-16/sort、Response/XHR、HTML树构建。
5. **默认交互与异步工作**：真正把页面负载移到worker、命中稳定node ID、编辑控件/IME接线、关闭/取消可靠。
6. **标准测试扩展**：固定WPT/Test262子集、当轮多内核差分、几何+像素+用户任务同时验收。
7. **排版与性能/GPU**：shaping、格式化上下文、增量依赖、真实shader/surface呈现；用工作负载收益决定优先级。

短期不要同时承诺完整HTML/CSS/ECMAScript、全部Web API、浏览器安全隔离和GPU加速。可以继续坚持自研内核，但必须公开支持边界；是否允许成熟native排版/JS组件应作为显式产品决策，而非在此评估中擅自替换项目。

## 10. 发布判断与限制

**当前建议：受控实验版/可信页面验证，不作为处理敏感账户或任意不可信网络内容的日常浏览器。** 这是对当前工程成熟度的判断，不否定项目的真实浏览器目标。

通用浏览器候选至少还需：安全策略全链、宿主/进程权限隔离、基础语言和排版正确性、真实GUI用户任务、稳定资源治理、外部标准子集与长期测试。HTTP200、有位图、1914函数未抛异常、真实spawn、显存读回一致，均不能单独替代这些标准。

本轮未完成当轮Edge/Firefox/WebKit完整差分、真机IME/读屏、多小时压力、操作系统沙箱攻防、敏感网站登录/支付、完整音视频/WebGL/Service Worker等验证。相关事项已列入方法和实施文档，未将“未验证”冒充“通过”。
