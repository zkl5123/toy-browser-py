# 第八轮评估方法与标准基线

## 范围与可证实程度

评估覆盖HTML/DOM、CSS、布局/文字、CPU/GPU绘制、JS/任务队列、网络/CSP/CORS/Cookie/缓存/Storage、GUI导航/工作进程、输入可访问性、测试工程与性能。不是逐行形式化验证，也不是安全无漏洞证明。

证据分级：
1. 当轮实测：真实项目执行、当轮Node/V8语义对照、真实回环HTTP、完整运行时回归。
2. 注入式实测：内存响应/客户端/超时替身或直接Python WebAPI调用；只证明所跨越的边界。
3. 静态证据：当前源码调用链；不据注释或模块名推断运行效果。
4. 历史参考：第五轮冻结Edge结果，仅对当前项目重跑，不冒充当轮浏览器执行。
5. 未验证：全量标准测试、实机IME/UIA、长时间运行、当轮多内核截图、真实GPU surface/device-lost。

## 标准依据

| 范畴 | 依据与链接 | 本轮采用方式 |
|---|---|---|
| HTML | [Parsing](https://html.spec.whatwg.org/multipage/parsing.html)、[Web app APIs](https://html.spec.whatwg.org/multipage/webappapis.html) | 完整文档/片段、任务检查点、脚本生命周期 |
| Fetch | [标准](https://fetch.spec.whatwg.org/)、[CORS check](https://fetch.spec.whatwg.org/#cors-check)、[filtered response](https://fetch.spec.whatwg.org/#concept-filtered-response) | 预检与实际响应分离、CORS网络错误、Origin、可见响应 |
| ECMAScript | [ECMA-262](https://tc39.es/ecma262/) | 严格相等、UTF-16、内建与微任务相关样本；不是全量语言验收 |
| CSS | [CSS specifications](https://www.w3.org/Style/CSS/specs.en.html) | 级联、选择器、布局模式的目标行为；几何参考来自冻结样本 |
| WPT | [testharness API](https://web-platform-tests.org/writing-tests/testharness-api.html) | 断言、异步完成、超时和外部符合性测试流程 |
| Test262 | [项目](https://github.com/tc39/test262) | 后续固定commit与特性子集的验收方案；本轮未运行官方全量 |

前续执行已获取Fetch、HTML与WPT文档用于核对。实现中的“CORS失败不得reject”的注释与规范相反，不能拿代码注释当标准。

## 样本来源与计数纪律

`fixture-provenance.json`记录从第七轮复制的脚本/样本及hash。复制历史测试在新轮执行，不覆盖旧轮证据。历史脚本内注释和evidence行号仍可能指向旧版本，本轮结论以本报告当前调用位置和结果为准。

- JS差分51例：分别统计日志原文/trim和状态原文/类别，不将格式归一化悄悄当完全相等。
- 新JS差分24例：同一源码分别送Node与项目引擎，不比较网络/DOM。
- 几何48框：x/y/w/h绝对误差均≤1px才通过；非视觉兼容率。
- 渲染32断言：既有标准反例，也有项目控制项和组件契约。29匹配、3不匹配还必须逐项裁决，不直接等同标准pass率。
- 历史安全21组：非统一pass/fail计数；ResponseTooLarge可代表修复生效，替身缺close属于探针失效，配额常量迁移不能由旧patch得出失效结论。
- 8组current probe与5组network probe：分别保留注入边界、回环请求序列和观测值，脚本成功退出只表示探针完成，不表示产品通过。
