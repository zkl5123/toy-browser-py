# 第八轮逐项改进实施方案

基线`551da74`。本文件是待实施计划，不是修复记录。本轮没有修改产品代码。18项按依赖排序；P0为面向不可信网页发布阻塞，P1为正确性/架构基础，P2为能力与性能扩展。

## 阶段与执行原则

顺序：Q01可信基线 → S01/S02/S03与A01安全闭环 → S04/H01/J01/A02文档及异步入口 → Q02/L01/U01 → P01/P02与发布治理。

每项交付必须包含：原缺陷最小复现、产品修改、反向/边界用例、默认调用入口证据、实际环境及未验证项。不得仅添加新辅助模块和单元测试就宣布默认功能完成。所有命令失败均保留原始结果；验收不能删除失败用例凑绿。

## 01 — R8-Q01：恢复可靠的测试基线（P1，先执行）

**模块**：tests/run.py、tests/test_browser.py、tests/test_p34_r4.py、runner contract测试。

1. 以本轮2871/2874结果建立缺陷清单；为三失败分别保存原始输出。
2. 历史导航测试改走公开API，明确back_stack是否只读投影；文档结构断言允许正确head，并增加doctype/comment节点语义；浮点断言采用有依据容差。
3. 将超时执行改为持有Popen句柄；communicate超时后终止进程树、回收、保存stdout/stderr，禁止访问TimeoutExpired.proc。
4. 加入“子进程未产summary、部分输出、非零exit、导入失败、未知only、SKIP、真实超时”契约。

**验收**：JSON/JUnit/退出码同源；失败返回非零；超时记TIMEOUT而非AttributeError；全量无未解释红项；不能把仅修断言当作标准符合性提升。依赖：无。

## 02 — R8-S01：分离CORS预检与实际响应授权（P0）

**模块**：network/net.py、network/request_context.py。

1. 拆PreflightResult与CorsResponseResult；前者只能允许发送并缓存方法/头/期限。
2. 实际响应每次重新校验ACAO/ACAC，不复用OPTIONS可见头或allowed。
3. 重定向每跳重算URL、origin taint、mode、credentials和策略；缓存命中也不能绕过授权。
4. 缺/错ACAO返回网络错误，不退化为成功opaque。

**验收**：复跑本轮network_probe：预检允许实际拒绝必须reject且无正文；预检拒绝必须无实际请求；相同目标不同origin/credentials缓存不串。依赖Q01。

## 03 — R8-S02：统一XHR正文、状态与错误事件（P0）

**模块**：scripting/js.py的_Xhr、FetchTransport。

1. 在设置status/body前消费统一CORS结果；网络/授权失败清空status/body/header。
2. 实现正确readystatechange/error/loadend顺序；HTTP404与网络失败分开。
3. 验证JS构造器与方法绑定，覆盖JS源码发POST而非仅Python对象直接调用。
4. 与fetch共用授权结果而非复制一套规则。

**验收**：真实回环无ACAO不能读SYNTHETIC_R8；有合法ACAO可读；onload不在授权失败时触发；POST/body/headers记录一致。依赖S01。

## 04 — R8-S03：补全Request/Response协议（P1）

**模块**：js.py._fetch/_fetch_response、request_context.py、net.py。

1. 归一化init.mode/credentials/redirect/method/body/headers/signal，拒绝非法组合和受限头。
2. CORS实际请求生成Origin；区分safelisted请求与需要预检的请求，不因任何header或仅include一概预检。
3. basic/cors/opaque/error分别过滤；cors头默认白名单，按Expose-Headers扩展；opaque status=0、url空、头/正文不可见。
4. 处理HEAD、redirect manual/error、单次body消费、bodyUsed与abort状态；保留HTTP错误响应非网络错误的语义。

**验收**：跨源/同源×三credentials×mode×方法×重定向矩阵；服务端请求记录与页面可见结果联合断言。依赖S01/S02。

## 05 — R8-A01：合并所有导航入口的安全上下文（P0）

**模块**：app/gui.py.load_url/_load_no_history/load_html/reload、browser.py、document_state_full.py、document_renderer.py。

1. 建立导航结果对象：final URL、origin、response headers、policy、trust、资源上下文、generation、取消令牌。
2. 首次、刷新、前进后退、replace、脚本导航共用commit_document；禁止远程html直接落到默认execute_all。
3. Host创建前绑定身份与策略，事件/timer/动态脚本复用文档执行许可。
4. 错误/about/file/inline采用明确上下文；清理旧Host/命中树/资源任务；失败不保留旧安全状态。

**验收**：本轮GUI CSP none探针始终before；远程默认禁脚本所有入口一致；政策异常fail-closed；旧导航迟到帧不能覆盖新页。依赖Q01，可与S01并行修改不同模块但交付统一集成验证。

## 06 — R8-S04：存储分区与Host生命周期原子绑定（P1）

**模块**：scripting/web_api.py、storage_service.py、Host初始化、GUI/CLI/worker入口。

1. 将origin/profile/tab/opaque token传入Host构造或一次性bind_document。
2. 在身份确定后创建Storage facade，不依赖调用方手动重新register_web_api。
3. 定义跨导航/标签/profile隔离、配额增量计算与失败原子性；对opaque按目标规范选择拒绝或明确受限语义。
4. 不让重绑覆盖location/history和事件订阅。

**验收**：同源新文档共享local；异源隔离；session仅同tab同源共享；opaque不串；配额真实触发；刷新/历史/worker入口同样通过。依赖A01。

## 07 — R8-H01：分离文档解析与上下文片段解析（P1）

**模块**：document/dom.py、html_pkg/build.py、tokenize.py、所有app解析入口。

1. 增加清晰parse_document与parse_fragment(context)，保留兼容入口但不供新导航使用。
2. 网络/文件顶层HTML强制document；无doctype仅影响quirks，不能切为fragment。
3. 保留doctype/comments节点与compatMode；编码与HTML错误恢复独立验证。
4. 导入固定树构建用例：table/select/template/格式化元素/外来内容，记录预期树与实际树。

**验收**：`<p>x`顶层具有html/head/body；同串在片段上下文产生正确片段；不破坏innerHTML/table上下文。依赖Q01/A01。

## 08 — R8-J01：脚本与异步生命周期的端到端符合性（P1）

**模块**：scripting/js.py、task queue、document_renderer、navigation。

1. 以24个已通过语义为保底，扩充固定版本Test262子集而非只测试修复点。
2. 为parser-inserted/defer/async、微任务检查点、异常清理、定时器取消、导航后任务失效建事件轨迹。
3. 网络fetch/XHR由异步结果驱动，不在UI线程同步完成；Promise由同一任务队列调度。
4. 对不支持语法/模块/内建明确异常与能力边界。

**验收**：trace与参考浏览器一致；长网络等待不阻塞UI；导航后旧timer不能改新DOM。依赖A01/A02。

## 09 — R8-A02：接通默认GUI工作进程与取消（P1）

**模块**：gui.py._commit_navigation、document_process.py、document_controller、frame_shared、gui_document_bridge。

1. 默认GUI提交只发导航命令，不同步fetch/JS/layout。
2. worker负责完整导航结果构建和文档计算；避免先在UI下载再说“worker加载”。
3. 命令/结果携带tab/document/navigation/generation；共享帧容量、所有权、释放与异常回收可验证。
4. Stop/关闭标签/新导航取消网络与脚本；隔离崩溃并重新启动对应工作单元。

**验收**：记录真实PID和默认入口；慢网络时心跳持续（项目建议95分位调度间隔<100ms，非规范硬指标）；取消后无旧帧提交；连续开关100轮无进程/共享段累积。依赖A01、S01；长期压力需单独批准受控范围。

## 10 — R8-Q02：建立外部符合性与浏览器差分基线（P1）

**模块**：tests/external、独立适配runner、CI配置。

1. 固定WPT/Test262上游commit与许可证，记录每例上游路径、特性、skip原因；自写改编用例必须标成adapted。
2. 接入testharness完成/超时与reftest结果，不能仅扫描PASS文本。
3. 当轮固定Chromium/Firefox/WebKit版本、字体、viewport/DPR，输出原始与差分证据。
4. 分离标准符合性、项目控制测试、环境失败、性能阈值。

**验收**：在干净环境可重跑同批测试，预期来源可追溯；不以51个历史样本宣称标准兼容率。依赖Q01、H01、J01。

## 11 — R8-L01：统一文本塑形、行布局与绘制（P2）

**模块**：typography/text.py、layout/layout.py、rendering/inline_layout.py、paint_engine.py。

1. 定义glyph run和cluster结果，字体fallback、advance、offset在布局绘制间复用。
2. 去除绘制阶段独立重新换行；命中、选择、光标采用同一cluster映射。
3. 扩充CSS动态失效、bidi、组合字符、CJK标点、emoji、分数字号测试。
4. 为复杂flex/grid/table增外部几何和reftest，不再只添加单一修复反例。

**验收**：不同DPR/缩放下布局绘制一致；选择与光标落在正确cluster；参考图误差有解释。依赖H01/Q02。

## 12 — R8-U01：真实输入法、键盘、可访问性验收（P2）

**模块**：editor_overlay、ui_a11y_bridge、gui输入路由。

1. 将逻辑编辑状态接到真实控件/组合事件；维护焦点、选区与composition生命周期。
2. 安全剪贴板/表单提交/Tab顺序、缩放滚动命中验证。
3. 将UIA树与事件实际发送到平台，name/role/value/state与焦点可被读屏感知。
4. 记录OS、IME、读屏版本和人工结果，不用mock作为系统支持证明。

**验收**：中文候选输入/取消/切焦点、键盘无鼠标操作、读屏朗读、地址栏TLS状态都有实机证据。依赖A01/A02/L01。

## 13 — R8-P01：以布局与显示列表为首要性能目标（P2）

**模块**：layout、css失效、paint_engine、GUI渲染调度。

1. 保留100/1000/5000基准，记录冷/热、内存峰值、主线程阻塞和阶段中位数。
2. 消除无效全量遍历、重复测量，缓存需携带样式/字体/viewport版本。
3. 视口裁剪、增量布局、damage rect与显示列表复用；验证更新正确性先于速度。
4. 将PNG编码移出常规交互帧；性能门限按同机基线制定。

**验收**：5000样本布局/emit成本下降且外部几何无退化；报告实测数字而非保证倍数。依赖A02/Q02/L01。

## 14 — R8-P02：GPU真正绘制与surface呈现（P2）

**模块**：rendering/gpu.py、gui_backend_boundary、CPU/GPU backend。

1. 能力声明先改为“CPU光栅+GPU上传”直到真实draw实现。
2. 按rect/border→image→glyph→clip/blend逐类GPU执行，保留CPU reference。
3. 真实surface常规帧不读回；截图明确capture；跟踪传输字节与GPU时间。
4. resize/device-lost/atlas淘汰/纹理回收全链处理。

**验收**：真实设备draw/submit证据、连续呈现、像素差分、GPU失效CPU回退；None设备探针不算真实GPU验收。依赖P01/Q02。

## 15 — R8-N01：补齐网络存储回归矩阵（P1）

**模块**：cookie_context、cache_validity、net、storage_service。

1. 单一上下文贯穿redirect/cache/fetch/XHR/subresource，不写缺省放行dict。
2. 覆盖Cookie host-only/PSL/Path/SameSite/credentials、多个Set-Cookie与POST。
3. 覆盖Vary、授权缓存、304头合并、重验证失败、隐私桶隔离。
4. 受控验证gzip/raw/POST/流式上限、超时、慢响应和取消；持续流也须增量限额。

**验收**：每项有回环请求记录与存储状态，不把单个异常阻止后的未执行分支计通过。依赖S01/S03/S04。

## 16 — R8-E01：锁定环境与可重现交付（P1）

**模块**：依赖清单、启动脚本、CI、测试环境报告。

1. 固定Python/依赖/字体版本，记录Tk/wgpu/PIL可用性；不要靠目录名判断真实版本。
2. 无GPU/Tk环境明确skip或CPU fallback；GUI验证使用完整环境。
3. 增加干净安装、启动、离线样本与测试入口验证。
4. 输出版本、依赖、测试结果与源码hash清单。

**验收**：另一干净Windows环境按说明成功启动并重跑核心测试；测试数/skip原因可解释。依赖Q01。

## 17 — R8-E02：收敛重复入口和能力文档（P2）

**模块**：app/browser.py、gui.py、document_renderer、js WebAPI拆分、项目docs。

1. 绘制“调用者→文档上下文→网络→脚本→布局→呈现”的唯一入口表。
2. 新旧兼容包装只做参数适配，不重建安全语义。
3. 将完成状态分为组件实现/默认接入/回环端到端/真实平台验收。
4. 按职责渐进拆分大模块，保留toy_browser包名与公开导入兼容。

**验收**：每项能力能定位默认调用者与测试证据；删除或标注失效完成声明，旧轮证据不覆盖。依赖A01/S03/A02。

## 18 — R8-R01：建立发布门槛与回滚（P1）

**模块**：CI发布流程、版本诊断、运行时能力开关。

1. P0、失败测试、安全矩阵不通过时阻断发布；不支持功能明确禁用。
2. 新导航/worker/GPU以独立开关逐步启用，保留CPU与可信输入退路。
3. 故障日志脱敏、限制长度；证书/错误页面不隐藏真实错误。
4. 建立回归包和版本回滚，重跑默认入口而非仅模块单测。

**验收**：连续基线通过、所有P0有反向测试；IME/UIA/GPU未验收时不能宣称完整支持。依赖本轮P0与Q01/Q02/E01/N01；不强制等待全部P2才能作为受限实验版本发布。

## 里程碑交付

- M1：可信红绿结果 + 所有P0关闭 + 默认远程策略一致。
- M2：文档/存储/解析/任务生命周期统一，默认GUI可取消异步导航。
- M3：固定外部符合性与新鲜多浏览器差分，文本及输入实机验证。
- M4：可量化性能收益与真实GPU绘制，能力声明与证据一致。

每个里程碑记录真实完成与剩余限制；本计划不预设工作日估算，不把未来验收写成已完成。
