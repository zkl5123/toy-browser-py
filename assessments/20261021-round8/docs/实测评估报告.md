## 1. 结论

项目已经是具有独立 HTML/CSS/布局/脚本/网络/绘制链的实验性浏览器内核，不能简单归类为截图演示器。上一轮提出的多个基础问题已实质修复：JS 严格相等与 UTF-16 等选定语义、CSS 权重和匹配缓存、Grid/Flex/Table 的选定几何、图片内容缓存键、字形图集覆盖、宿主私有属性防护、部分 CSP/Cookie/响应限额和测试失败统计均有改善。

但当前仍不满足可安全日常浏览任意网页的发布条件。关键阻塞集中在**安全决策贯穿所有入口、标准错误语义、默认 GUI 调用链、外部测试覆盖**，而非继续增加纯逻辑接口的数量。本轮实证包括：预检放行被错误用作实际响应授权、XHR 跨源正文可读、GUI 刷新/历史路径丢失 CSP 与脚本信任判定、标准文档与片段入口混用。

不提供“整体兼容率”或单一百分制评分：有限定向样本、自有测试和历史浏览器参考不足以产生这样的数字。

### 三项回归失败的解释

1. `test_gui_back_forward`：旧测试直接修改 `back_stack`，而当前实际导航依赖 `_hist` 游标。重放得到 initial=`demo.html`、back=`about:blank`、forward=`about:blank`。这是旧测试/公开投影契约与新历史实现冲突，需要公共入口测试裁决，不能直接推断所有正常后退操作都失败。
2. `test_p24_comment_doctype_dropped`：当前自动补出 `head`，旧断言只允许 document/html/body/p，故失败。补 `head` 是正确方向；同时该测试“丢弃doctype/comment”的整体目标也不等于标准DOM要求。应改为验证节点类型、渲染忽略与文档模式，不能删掉正确的 head 来迁就旧断言。
3. `t5_half_lead_cache`：比较值为 `15.146875` 与 `15.146875000000001`，浮点精确相等触发失败。应以有依据的布局容差断言，保留明显几何回归的失败能力。本轮没有修改断言或把它计成PASS。
