# 第八轮渲染与标准差距审计

基线`551da74`。本轮沿用R7样本并复核接口，结果见`render-probes.json`、`comparison.json`及`pipeline_profile.json`。历史探针中的evidence行号来自R7，仅用于追溯；本报告引用当前路径和确认过的调用位置。

## 1. 已证实的修复

32个历史断言中29个原始匹配。HTML的带引号大于号、首个重复属性、RCDATA实体、空白文本、隐式tbody、script rawtext均符合该样本预期。CSS的组合权重、未知伪类拒绝、not、属性、混合组合符、ID胜多类、结构/ID缓存和important均通过选定样本。

Grid row-gap现在相差30px（20高+10间距），显式第二列为50px；Flex换行grow宽度为50/50/100；colspan=2宽100。历史Edge的48个几何框均在1px误差内，说明这些既有回归已修好，但不代表复杂布局已经全面标准化。

GPU图片两张同尺寸红/蓝内容分别驻留，缓存miss=2、upload=2，内容键不同；图集有非零alpha，family/Unicode/字号样本字节不再相同；DisplayCommand带font_family；独立InlineLayout保留混合字号和style。这些是实质进展，不应继续抄写R7缺陷。

## 2. 原始三个不匹配不能直接称为三个缺陷

| 原始断言 | 原因 | 本轮裁决 |
|---|---|---|
| html_implied_document_element | dom.parse无doctype字符串默认走片段，显式True才补html | 模块已支持完整文档；应用入口仍未强制模式，入口契约缺陷保留 |
| gpu_present_needs_surface | 探针__new__后注入device=None，CPU回退present可返回True | 该样本不具备“真实GPU无surface”前提，不能证明GPU仍假呈现 |
| gpu_verify_helper_rgb_conversion | GPURasterizer(None)现在要求有效设备；受管环境缺wgpu，完整环境None.create_texture失败 | 不再是旧bytearray.extend(int)错误；无效设备探针不算产品回归，真实设备需专门验收 |

保留原始JSON以便复查，不删失败或改预期凑全绿。最初历史脚本缺_gate导致中止的日志也保留；当前适配只补构造器前提，不改产品代码。

## 3. HTML与DOM下一步

`document/dom.py:30–47`通过document_mode=None按doctype/html文本猜测文档类型。`app/browser.py:125`、`app/gui.py:408/938`及document_renderer仍直接parse(html)。真实HTTP HTML即使没有doctype也应走document算法，只是quirks mode不同；innerHTML等片段解析须携带上下文元素，不能依字符串猜。

实施：公开parse_document和parse_fragment(context)；导航入口强制document，DOM片段入口显式上下文；保存doctype/compatMode/编码；建立可序列化树快照差分。进一步覆盖table foster parenting、格式化元素重建、select/template、SVG/MathML边界、实体错误恢复。不存在当轮全量html5lib/WPT树构建符合性证据，不推断这些均已坏或均已实现。

## 4. CSS、布局与字体

已修复有限反例后，应转向外部用例和动态改变：DOM增删、class/style更新、媒体查询尺寸切换、字体加载后重排、伪元素、继承与自定义属性、inline/block混排、百分比/auto/min-content/max-content。各机制先通过固定几何fixture，再做真实像素差分。

CPU已有真实TTF字形，不应描述为“纯ASCII位图”。当前family传播改善不等于复杂文字排版闭环。需按glyph shaping的输出统一布局与绘制：glyph id、advance、offset、cluster、fallback font；测试连字、组合音标、阿拉伯文/混合方向、CJK标点、emoji序列、不同DPI与分数字号。不得让布局逐字符宽度与绘制重新换行各自决定文本位置。

独立InlineLayout样本通过只证明组件；默认布局是否消费相同glyph/line结果仍应通过端到端命中、选择、光标与截图验证。平台IME和选择区的实机验收见GUI专题。

## 5. GPU实际路径与实施边界

`rendering/gpu.py:943–984`明确执行：rasterize_to_canvas→RGB转RGBA→upload_rgba8。即使设备是真实GPU、图片/字形缓存正确，最终像素仍由CPU生成，不能将其作为GPU光栅化性能证明。

gui_backend_boundary提供surface门控、读回策略、resize/device-lost决策，属于有价值的边界设计。当前无本轮真实swapchain呈现、设备丢失恢复和连续帧不读回证据，报告保持未验收，不沿用R7“present恒占位”的过时结论。

实施：先明确CPU后端为基准；GPU逐类接管rect/border/image/glyph/clip/blend，以相同显示列表和像素容差验收。记录实际CPU/GPU耗时及上传/读回字节；常规帧走surface，截图才读回；resize/设备丢失/资源淘汰可恢复。只有GPU执行draw/compute并证明端到端改善，才修改产品能力声明。

## 6. 性能证据

100/1000/5000样本三次中位render_total分别约535/2616/12213ms（PNG另计约833–839ms）。5000样本布局约6502ms、显示列表生成2850ms、CPU光栅314ms。应优先减少布局和显示列表遍历、只更新脏子树与可见区域、避免GUI线程执行长任务，而非假定所有问题由光栅引起。

原始计时没有与旧轮相同硬件负载的严格控制，因此不宣称跨轮性能提升或退化倍数。固定视口导致光栅时间近似不变并不表示完整长页面没有内存/滚动成本。

## 7. 截图与未验证项

本轮生成basic、cjk、forms、emoji_symbols四张PNG。图片读取接口不支持当前模型，未完成视觉判读；没有当轮Edge/Firefox/WebKit截图和新像素兼容率。PNG文件存在/可解码只证明工件有效，不证明排版正确。
