## 本次完成的修复（已落入 layout.py）

### 1. `LayoutBox.border_rect()` 接缝（约 L385）

- 内部 `rect` 记录在内容盒原点（`content_x0 = x + margin_l + padding_l`，`content_y0 = y + padding_t`；`rect.w` 为内容宽）。
- `getBoundingClientRect()` 是边框盒：原点回退 **padding**（不含 border——内核 legacy 偏移本就未计 border，属已知近似），尺寸 = 内容 + padding + border。
- 修正过程：初版按 padding+border 回退原点，导致 table/grid 的 x = −1（零 padding 盒子被双重回退）；改为仅回退 padding 后 blocks 的 a x=18、table x=0、grid x=0 全部精确。
- 评估探针 `toy_layout_runner.py`（约 L53）改用 `bx.border_rect()`。

### 2. 块级兄弟累积改为边框盒高度（约 L2437-2472）

- 内容堆按 `rect.h + pad_t + pad_b + bdr_t + bdr_b`（边框盒高）推进，而非仅内容高，使后续兄弟定位包含上盒的 padding/border。

### 3. Grid 列轨道边框盒（约 L3335）

- `box-sizing: border-box` 且列数等于 `fr` 数时，列轨道按**内容宽**重算；单元格 stretch 高度在 border-box 下扣除容器 padding + border。

### 4. Flex 主轴内容基准（content basis）

- content-box 项：`width:40px;padding:5px` 的 flex 基准应为 40（内容），legacy 无条件减 padding 得 30，位置整体偏移；已修正 basis/cap/placement 三处，`flex_padding_border` 的 c1/c2/c3 x 现为 61/123/185，精确对齐。
- border-box 项：基准 = 显式宽 − padding − border（主轴）。

### 5. Flex 交叉轴

- 容器为 border-box 时 `cross_avail` 扣除 padding + border；
- 交叉轴 center/end 按**外边距盒**（margin box）交叉尺寸居中，修复红色区域整体偏移 4px（评估报告 §"布局修复仍有边界错误" 中"反向 Flex 居中/ Flex gap 上移 4px"两项）。

### 6. 顶部外边距折叠契约（`_fold_margins` 文档 + `layout_block` 约 L2316-2360）

- CSS2.1 §9.5.1.2：父顶边与其首个流内块级子顶边无 padding/border 间隔时，折叠量为 `max(parent.mt, child.mt)`，折叠量凸出在父顶边**上方**。
- 实现：`y += bx.margin.top - collapsed`（推进父的流 y 越过自身顶边）；首子自身顶边距不再回加（L2450-2462 的 `if i == 0 or prev_block is None: pass`）。
- 非折叠容器（flex/grid/table/BFC/绝对定位/带 padding 或 border）保持完整顶边距。

## 未完成项（截至本次收尾，3 个几何 diff）

用户决策：**停止继续修复**，以下为遗留 diff 与已定位的根因，供下轮继续。

### D1. `layout_blocks.a`：y = 0 vs Edge 10（x/w/h 精确）

- 页面未设 `body{margin:0}`，UA `body` margin 8px 生效。
- Edge 语义：body 顶边距 8 与 `.a` 顶边距 10 折叠为 10，`.a` 边框盒顶 = 10。
- 内核现状：折叠推进 `y += bx.margin.top - collapsed = 8 - 10 = -2` 发生在 **body** 的 `layout_block` 内部，但 `layout()` 入口对 html 起点的 y=0 未计入 html→body 链上的折叠量传递；`.a` 内部 `rect.y=5`（content_y0 + half_lead 链），`border_rect()` y = 5 − 5(pad_t) = 0。
- 根因定位：首子顶边距折叠推进尚未贯通到 body 层级的流起点（`.a` 内容 y 需 15 才能得边框盒 y=10）。

### D2. `layout_blocks.b`：y = 70 vs Edge 80（x/w/h 精确）

- 与 D1 同源：折叠量 10px 缺失导致 `.a`/`.b` 整体偏高 10。`.b` = a 边框盒顶(10) + a 边框盒高(50) + gap(max(a.mb=10, b.mt=20)=20) = 80；内核算得 70。
- 修复 D1 后 D2 预计同步消除。

### D3. `layout_table.tab`：w = 75.12 vs Edge 70.08（h=60.4 vs 61，x/y 精确）

- 收缩适配（shrink-to-fit）列宽偏宽约 5px。
- 根因定位：`_layout_table` 中 `border-collapse: collapse` 的共享边框计半（`_bw_lr = (border.l+r)/2`）与表格外边框单次计入的边界处理（约 L3535、L3564-3581）仍有 5px 偏差；Edge 2×2 单字符表 ≈ 70px。
- 方向：列自然宽在 collapse 模式下的共享/外边框分配需再核一遍（相邻两列各记半边框后，表格左右外边框只各记一次）。
