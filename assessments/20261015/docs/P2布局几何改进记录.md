## 本次完成的修复（已落入 toy_browser/layout/layout.py）

### 0. P33.R2-2 — D1/D2/D3 三个遗留 diff 全部消除

**D1/D2：首子顶边距折叠贯通到 body 流起点（`layout_block` 约 L2234-2290 + 子循环约 L2488-2511）**

- 模型：基线 P26.1 契约（盒自身顶边距永不在内容内消耗，父级子循环负责
  兄弟 gap / 首子不推进）保持不变；**唯一例外**是顶层流（父为
  `<body>`）：body 自身顶边距（UA 8px）不被 body 子循环消耗，故首个
  流内块级子顶边距"替换"它——子内容原点推进 `child.margin.top`
  （仅当 `body.margin.top > 0`；`body{margin:0}` 时回退基线模型，
  表格用例 y=0 保持精确）。
- 父级子循环在首子布局后同步推进 `child_y += cb.margin.top`
  （同条件），后续兄弟自首子实际边框盒顶量起 → D1 `.a` y=10、
  D2 `.b` y=80 均精确对齐 Edge。
- P26.1 回归防护：div>div>child 链（父非 body）保持基线模型
  （`test_p26_margin_collapse_parent_child` / `empty_block` 通过）。

**D3：`border-collapse: collapse` 表格列宽分配（`_layout_table` 约 L3575-3645）**

- collapse 模式下每列自然宽 = 文本 + 全 padding − 半边框对
  （`_bw_lr = -(b.l+b.r)/2`）：相邻单元格的共享边框只绘制一次，
  边框像素计入列间空隙/表格外缘，不再计入列内容；
- 表格外缘 = 最外列边框对的剩余半段（`(table.b.l+b.r)/2`），
  表格元素自身边框与单元格共享、不单独计数；
- 表格 `rect.w` 存"总宽 − 完整边框对"，`border_rect()` 回加
  完整边框对后报出正确边框盒宽（2×2 单字符表 75.12 → 70.12，
  Edge 70.08，0.04px 内）；
- `bx.border_collapse` 为 False 时探测 row/cell 计算样式
  （cascade 不把 collapse 继承进 `<tr>`/`<td>`），表格自身声明
  collapse 时补置标志（本测试用例表格标志已为 True，探测为保险路径）。

### 1. `LayoutBox.border_rect()` 接缝（约 L385）

- 内部 `rect` 记录在内容盒原点（`content_x0 = x + margin_l + padding_l`，`content_y0 = y + padding_t`；`rect.w` 为内容宽）。
- `getBoundingClientRect()` 是边框盒：原点回退 **padding**（不含 border——内核 legacy 偏移本就未计 border，属已知近似），尺寸 = 内容 + padding + border。
- 修正过程：初版按 padding+border 回退原点，导致 table/grid 的 x = −1（零 padding 盒子被双重回退）；改为仅回退 padding 后 blocks 的 a x=18、table x=0、grid x=0 全部精确。
- 评估探针 `toy_layout_runner.py`（约 L53）改用 `bx.border_rect()`。

### 2. 块级兄弟累积改为边框盒高度（约 L2437-2472）

- 内容堆按 `rect.h + pad_t + pad_b + bdr_t + bdr_b`（边框盒高）推进，而非仅内容高，使后续兄弟定位包含上盒的 padding/border。

### 3. Grid 列轨道边框盒（约 L3335）

- `box-sizing: border-box` 且列数等于 `fr` 数时，列轨道按**内容宽**重算；单元格 stretch 高度在 border-box 下扣除容器 padding + border。

### 4. Flex 主轴内容基准（content basis）

- content-box 项：`width:40px;padding:5px` 的 flex 基准应为 40（内容），legacy 无条件减 padding 得 30，位置整体偏移；已修正 basis/cap/placement 三处，`flex_padding_border` 的 c1/c2/c3 x 现为 61/123/185，精确对齐。
- border-box 项：基准 = 显式宽 − padding − border（主轴）。

### 5. Flex 交叉轴

- 容器为 border-box 时 `cross_avail` 扣除 padding + border；
- 交叉轴 center/end 按**外边距盒**（margin box）交叉尺寸居中，修复红色区域整体偏移 4px（评估报告 §"布局修复仍有边界错误" 中"反向 Flex 居中/ Flex gap 上移 4px"两项）。

### 6. 顶部外边距折叠契约（`_fold_margins` 文档 + `layout_block` 约 L2316-2360）

- CSS2.1 §9.5.1.2：父顶边与其首个流内块级子顶边无 padding/border 间隔时，折叠量为 `max(parent.mt, child.mt)`，折叠量凸出在父顶边**上方**。
- 实现：`y += bx.margin.top - collapsed`（推进父的流 y 越过自身顶边）；首子自身顶边距不再回加（L2450-2462 的 `if i == 0 or prev_block is None: pass`）。
- 非折叠容器（flex/grid/table/BFC/绝对定位/带 padding 或 border）保持完整顶边距。

## P33.R2-3 — layout_table.tab 高度差（h 60.4→61.4，w 75.12→70.125）

> 2026-10-15 会话（本轮）：远端 P33.R2-2 提交声称 48/48，但本地复现 47/48，
> 唯一遗留 diff 为 `layout_table.tab`（toy w=70.12/h=60.4 vs Edge 70.078/61，
> h 差 0.6px 刚好越出 0.6 容差边界）。本轮修复后 h=61.4，与 Edge 61 差 0.4px，
> 本地复现 **48/48** 达成。

**根因**：`_layout_table` 行距（row pitch）legacy 用 `cell.outer_height()`
（内容 + padding + border + margin），collapse 模式下每行多算了完整边框对
2px（行高 31.2 vs 边框盒 29.2）；同时行间的共享行边框（collapse 下只画
一次，归属行间隙）未计入。

**修复**（`toy_browser/layout/layout.py` `_layout_table` Phase 2，约 L3694-3758）：

- 行高改用单元格**边框盒高**（内容 + padding + border），不再含 margin；
- collapse 模式下每个内部行边界追加一次共享行边框
  （`max(本行底边, 下行顶边)`，CSS §17.4.3.1 宽边胜出，等宽只画一次），
  末行无下边界；
- 表格 `rect.h` = 行距累计（边框盒 + 共享边界），`border_rect()` 回加
  外边框对后报出边框盒总高：2×2 用例 child_y = 29.2 + 1 + 29.2 = 59.4，
  边框盒 h = 61.4 ≈ Edge 61（0.4px 内）。

**附带**：`_verify_all.py` 第 8 节旧断言 `table w shrink-fit` 期望值
35.8（旧列宽公式）更新为 31.8（P33.R2-2 D3 的 collapse 半边框列宽
公式 + rect.w 存内容宽），容差 2.0 不变。
