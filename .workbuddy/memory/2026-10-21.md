## R7-A02 第 3 点：版本化 IPC 投递路径接线（合并/背压/取消确认/门控）（提交 03929bb）

### 决策
第 3 点的决策层（`CommandCoalescer` / `BackpressureGate` /
`CancelTracker` / `NavVersionGate`）此前只在 `TabBrowser.__init__` 里
被**实例化**——没有任何入口消费，"版本化 IPC"是宣称不是行为。本批
把它们接到**真实 UI 投递路径**（nav / resize 投递 + drain 收帧 +
关标签 / 关窗口回收）。

### 接线（gui.py）
- 新增 `_r7_a02_submit(cmd, flush=True)`：**统一命令提交入口**——
  先背压（`inflight` 达 `BackpressureGate` 上限则拒收并计 dropped），
  再合并（resize/scroll 同 (tab, navigation_id, kind) 只留最新）。
  - `flush=True`（默认）提交后立即投递合并结果，返回**真实 post
    结果**（关标签 False 的既有契约保留）；
  - `flush=False` 攒批（返回 True=被接纳），由 `_r7_a02_flush_
    commands()` 统一投递——批量提交（拖拽窗口 / 连续滚轮）走这条。
- 新增 `_r7_a02_flush_commands` / `_r7_a02_discard_pending` /
  `_r7_a02_request_cancel` / `_r7_a02_ack_cancels` /
  `_r7_a02_abandon_cancels` / `_r7_a02_gated_frames` +
  `_r7_a02_seq` / `_r7_a02_stale_dropped` 两字段。
- `_g07_post_nav` / `_g07_post_resize` 改走 `_r7_a02_submit` 并带上
  tab 当前 `navigation_id`；`_g07_drain_frames` 收帧后先
  `ack_cancels`（cancelled 帧确认在途取消）再 `gated_frames`
  （旧导航迟到帧 + 同导航内不推进帧丢弃 = "旧任务不可覆盖新页"，
  丢弃计数进 `stale_dropped`）。
- `_g09_close_tab`：`abandon_cancels(tab)` + `discard_pending()`；
  `_g07_doc_server_shutdown`：终止子进程**前**先丢弃待投命令（不往
  将死的进程投命令）。

### 关键语义区分（不冒充通过）
- `CancelTracker.abandon_tab(tab)` 是新增方法：关标签 = 取消请求
  **作废**（任务随标签丢弃）；**不等于** `ack_tab`（worker 确认取消
  完成）。两者混用会伪造"取消已被确认"——测试里显式断言
  `abandon` 后 `is_acked(token) is False`。
- `DocumentProcessPool.inflight()` / `DocProcessServer.inflight()` 新增
  公开方法（在途命令 + 在途帧），背压深度**不**去读私有字段
  （IPC 面不泄漏内部结构）。

### 不冒充通过边界（本批如实标注）
- **合并**只在"调用方用 `flush=False` 攒批"时才真正生效；当前 UI
  单次只提交一条 resize（默认 `flush=True` 立即投递），行为与既有
  一致——合并收益要等批量提交路径（拖拽 / 滚轮连发）接入。
- **取消确认**已接在 drain 路径，但**没有 stop 按钮 / 取消导航的 UI
  入口**，`_r7_a02_request_cancel` 目前只被测试消费，不宣称"用户
  可见的取消"。

### 测试（test_r7_a02_ipc_trace.py，29/29 @ 3.11.9）
- 静态：`_g07_post_nav` / `_g07_post_resize` 函数体调
  `_r7_a02_submit`；`_g07_drain_frames` 函数体调
  `_r7_a02_gated_frames` + `_r7_a02_ack_cancels`（按函数体切片断言）。
- 动态（tkinter 门禁，缺库 SKIP）：
  - 背压：limit=1 时第二条命令被拒收 + `dropped==1`；
  - 合并：3 条 resize 攒批 → `pending==1` / `merged==2`，flush 后

  - 门控：旧导航帧（nav 2<3）丢弃、同导航 frame_id 不推进丢弃、
    frame_id 推进放行，`stale_dropped==2`；

## R7-A02 第 5 点：坏脚本/慢页单 tab 隔离 + 关窗有界回收（提交 9e4cba9）

### 决策
方案第 5 点原文："慢页与坏脚本不影响其他标签；关闭窗口先停止任务/
回收子进程，再销毁 Tk root"。本批把"坏脚本不影响其他标签"从**空话
变成真接线**——发现并修掉一个真实缺陷：`_do_doc_work` 的渲染异常会
传播出 `worker.handle()`，杀死回退态的父进程或子进程循环（旧行为
`result_q.put({"error":...})` 后 **break** → 子进程退出 → 整池挂），
正是审计点名的"坏脚本连累其他标签"。

### 坏脚本隔离（document_process.py）
- `_do_doc_work` 内 try/except 兜住，返回**有限摘要**（≤128 字符，
  `script:<Type>:<msg>` 截断；None=成功）；摘要记 `_last_doc_error[tab]`。
- `handle` 两处调用点消费错误 → 该 tab **错误帧**：`ok=False` +
  `error_category="script"` + payload 白名单键 `error_category`（摘要，
  过 `validate_frame` 与 `FramePayloadContract` 父进程可见面校验）。
- 子进程循环：handle 异常 → 错误帧 **continue**（不 break、不退
  进程）；帧都构造不出才回退 `{"error": ...}`（仍不退出）。
- `doc_error_for(tab)` 访问器；`drop_tab` 清理；**成功渲染后摘要
  自动清除**（坏 tab 不是终身判决）。
- `_limited_error_summary()` 模块函数（摘要口径与
  `FramePayloadContract._MAX_STR_LEN` 一致）。

### 慢页隔离（gui.py，判定层 + drain 接线）
- `_r7_a02_note_task(cmd)`：记 `(tab, navigation_id) → monotonic`
  提交时刻；新导航清除该 tab 慢页标记。
- `_r7_a02_isolate_slow_tabs(frames, now)`：帧到达=任务完成；
  过期未产帧的 tab 标记 `_r7_a02_slow_tabs` + `slow_dropped++`，其
  **迟到帧**在版本门控之前被隔离；其他 tab 帧放行。`now` 注入不读
  时钟；`_r7_a02_slow_tab_timeout` 默认 **0=不启用**（不误伤真实
  spawn 异步延迟——宁可不用也不能误杀）。
- `_g07_drain_frames` 在 ack/gate 之前跑隔离；`_r7_a02_describe`
  加 `slow_tabs/slow_dropped/timeout` 诊断。

### 关窗有界回收（gui.py + document_process.py）
- **真缺陷修复**：`DocProcessServer.shutdown` 在 `terminate()` 后
  **没有二次 join**——terminate 是异步发信号，发完立即查
  `is_alive()` 可能仍 True，"关闭后无遗留子进程"根本不可断言。补
  `join(timeout=0.5)`。
- `_g07_doc_server_shutdown` / `_on_window_close` 记录关窗顺序到
  `_g07_close_order`：`stop_tasks → server_shutdown → destroy_images
  → root_destroy → root_quit`（先停任务/回收子进程，再销毁 Tk root
  ——顺序是可测证据，不靠读代码"感觉对"）。

### 不冒充通过边界（如实标注）
- 慢页隔离只保证"被标记慢的 tab 迟到帧不覆盖新页、其他 tab 不受
  影响"；"慢页期间 UI 心跳持续 / 输入 P95≤100ms"需要事件循环 tick
  + 非阻塞 worker，**未实测**（留活显示批次）。
- 坏脚本隔离是真实接线，但"任意真实坏脚本"未 fuzz——本批用**注入
  异常**证明"传播被兜住"这一契约。
- Tk root 销毁本身需真机窗口（活显示批次人工验证）；本批断言顺序
  + 进程退出，不断言窗口视觉结果。

### 测试（新建 tests/test_r7_a02_slow_page_isolation.py，9/9 @ 3.11.9）
- 坏脚本：navigate + resize 错误帧（ok=False/script/有限摘要/过 IPC
  校验）、其他 tab 照常渲染、恢复后摘要清除、drop_tab 清除；
- 子进程循环静态契约（continue 在、handle 到 continue 间无独立
  break 语句）；
- 真实 spawn 池 shutdown 后无遗留子进程（进程退出 + exitcode +
  is_spawned False）；
- 慢页隔离：过期未产帧 tab 标记慢页、迟到帧隔离、好 tab 帧放行、
  新导航解除隔离、timeout=0 不过滤；
- 关窗顺序五步断言 + 重复关闭幂等 + gui 关窗路径回收真实子进程。

- 受管 3.13.12 fast：2199 passed / 0 failed / 9 errors（既有 tkinter
  缺库）/ 34 skipped。
- 完整 3.11.9 --full：2761 passed / 3 failed / 0 errors / 0 skipped。

## R7-A02 第 4 点：连续帧 buffer 接呈现层（提交 b7c7943）

### 决策
第 4 点原文："帧用连续 buffer 或受控共享内存，不序列化整棵 Python
对象图；父进程不接触 worker 内部 Host。"决策层
（`FrameBufferSpec` 布局 / `FramePayloadContract` 父进程可见面）与
drain 挂校验此前已就位，但 `DocFrame.frame_spec` **从不填充**、
`buffer` 句柄**从不产生**——"连续 buffer"是个空字段不是行为。本批
把呈现层消费侧接上。

### worker 侧（document_process.py）
- 成功渲染帧（navigate 带 html / resize / scroll 重排）填
  `frame_spec`（rgb8，几何取自**实际渲染位图**）+ payload
  `buffer` 句柄 `{id, size, format, width, height}`（布局引用，
  **不**携带像素数据）；`size = w×h×3 = spec.total_bytes()`。
- 每次成功渲染分配**单调递增 buffer id**（`_buffer_seq` /
  `_last_buffer_id[tab]`），父进程据此区分"哪一块像素"。
- **失败帧 / 未渲染身份帧刻意不带** spec/句柄：失败不宣称像素；
  不给没渲染的帧挂旧位图布局。
- `buffer_handle_for(tab)` 访问器；`drop_tab` 清理 buffer id。
- `DocProcessServer` 加 `last_bitmap_for` / `buffer_handle_for`
  代理（读父进程内置同步 worker；多核态返回 None，不代子进程
  "变"出像素）。

### 呈现层（gui.py）
- 新增 `_r7_a02_apply_frame_buffer(frame)`：
  1. `spec.layout_ok()` 不过 → 拒收；
  2. 句柄过 `FramePayloadContract`（带 pixels 数据键等越面 → 拒收）；
  3. **回退态**：经 `server.last_bitmap_for(tab)` 取父进程 worker
     真实位图 → `CPUImage` 连续 buffer，几何 / 字节数与 spec 一致
     才应用（错位即拒收，不错位上屏）；
  4. **多核态**：返回 None + 计 `layout_only`——不把"有句柄"当
     "像素已到父进程"。
- `_g07_drain_frames` 在版本门控**之后**逐帧应用（被丢弃的旧帧
  不应用 buffer）；计数 `applied / layout_only / rejected` 进
  `_r7_a02_describe`。

### 不冒充通过边界（测试显式锁定）
- 多核态父进程拿不到子进程位图 → apply 返回 None 计 layout_only；
  真实 mmap / posix 共享段留活显示批次。
- 真实 spawn 冒烟已过：子进程 navigate 带 html 真实渲染 → 帧经
  pipe 完整带回 `FrameBufferSpec`（pickle 往返）+ 句柄，父进程
  drain 不拒收、`last_bitmap_for` 为 None（诚实口径）。

- 静态：`handle` 构造 FrameBufferSpec + 句柄（无 pixels/data 键）；

- 动态：navigate/resize/scroll 帧带 spec+句柄（过契约 + drain 不

## R7-S02 第 6 点：被禁止请求不得先发包再丢响应——POST 路径补发送前判定（提交 7cfb20e）

### 背景
方案第 6 点子项"被禁止请求不得先发包再丢响应"。GET 路径早已实现
（`request_context` 提供时先 `evaluate_request`，denied → 占位响应
status=0，不发包）；但审计发现 **POST 路径是真缺陷**：`HttpClient.post`
只把 decision 用于预检标记（`requires_preflight` 判定），**从不检查
`decision.allowed`**——CSP 拒绝（connect-src 'none'）、可阻断混合内容
（https 文档 + http 目标）、不支持 scheme 的 POST 照样发出。GET 拦、
POST 不拦，两边行为不一致。

### 修复（net.py）
- `HttpClient.post` 在方法顶部（旧 `UnsupportedScheme` raise **之前**）
  加与 GET 同口径的发送前判定：`request_context` 提供时先
  `_admit_request_context`，denied → 直接返回占位响应（status=0 +
  denied=decision + 跨源敏感头剥离）——不构建 body、不附 cookie、
  不发包。无 request_context 的 legacy 调用方保持 `UnsupportedScheme`
  抛出（契约不变）；带 context 时 scheme 由 `evaluate_request` 统一
  拒绝（与 GET 一致，GET 路径无 scheme raise）。
- 下方预检块复用已剥离的跨源头（原来剥两次，口径收敛）。

### 判定顺序细节（不冒充通过）
`evaluate_request` 的顺序：scheme(step3) → deadline(step4) → 混合
内容(step5) → CSP(step6)。测试里 CSP 用例**必须**用 `http://` 文档源
（`https://` 文档 + `http` 目标会被混合内容先行拦截——那是第 3 点
的正确行为，不是 CSP 路径）。

### 测试（test_r7_s02_s03_policy_cookies.py，54/54 @ 3.11.9）
- `test_s02_post_denied_csp_does_not_hit_wire`：connect-src 'none'
  拒 POST，服务端 POST 计数 0，`denied.blocked_by == "csp"`。
- `test_s02_post_denied_unknown_scheme_does_not_hit_wire`：ftp://
