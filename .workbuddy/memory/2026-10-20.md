## R7-A02 第 6 点：文档工作模式 + 能力声明真实性校验（Task #66）

承接上一批（版本化 IPC + 心跳/trace），关闭审计点名的原话：

> "现有 worker 存在且 spawn，但默认导航仍同步，worker handle 主要
> 返回 URL/版本状态；**不能据名称宣称已多核渲染**。"

### 核心判据（本模块的立论）
不是"有没有 worker / spawn 这些**名词**"，而是**文档工作（解析 /
样式 / 布局 / 绘制）在哪执行**：
- 默认导航 `gui._commit_navigation` 仍**同步**调 `page.load_url()`
  → 活在主线程。
- 既有 `DocumentProcessWorker` 处理的是**紧凑身份计数**
  （doc_id/nav_epoch/frame_id/navigation_id），**不**执行真实解析/
  样式/布局/绘制 → 即使真实 spawn，也只是"管道通了"，**不是**
  多核渲染。

### 新增 `toy_browser/app/doc_process_mode.py`（纯逻辑）
- `DocWorkMode` 三态 + `_MODE_CAPABILITIES` 能力表：
  * `MODE_SINGLE_DEBUG`（默认，活在主线程同步）
  * `MODE_WORKER_IPC`（子进程 spawn 且 IPC 通，但 worker 只做紧凑
    IPC/身份计数）
  * `MODE_WORKER_FULL`（worker 持 DocumentSession 执行真实文档工作，
    **当前未接通**）
  * 能力键：`multi_core_rendering` / `worker_isolation` /
    `ui_nonblocking_navigation` / `frame_ipc`。
    **只有 WORKER_FULL 的 multi_core_rendering = True**。
- `detect_doc_work_mode(navigation_is_sync, worker_does_doc_work,
  worker_spawned)`：按**真实接线**探测（不靠名字猜）。
  `worker_does_doc_work` 真 → FULL；否则 `worker_spawned` 真 →
  IPC；否则 SINGLE_DEBUG。默认调用返回 **SINGLE_DEBUG**（如实）。
- `CapabilityClaim(name, capability, mode)` + `is_truthful()` /
  `untruthful_reason()`：用**能力表**校验（非比档位）。越级声明
  （WORKER_IPC 下宣称"已多核渲染"）判 False 并给原因。
  `claim_multi_core_rendering(mode)` 是审计点名场景的便捷入口。
  保守：未知能力 / 未知模式均按**不真实**处理。
- `SingleProcessDebugMode`：**显式**单进程调试模式（审计"保留"）。
  与隐式回退区分：`enable(reason)` 主动 opt-in vs
  `mark_auto_fallback(reason)` 被动；`effective_mode(detected)`
  显式开启时**强制** SINGLE_DEBUG（即使探测到 worker_full），
  保证调试态下活一定在主线程可单步。

### 提交 1 `7a68b83` — 纯逻辑决策层
新增 `toy_browser/scripting/script_trust.py`：
- `classify_url(url, creator_trust)` 四档信任类。**local** =
  file:/about: 等无网络来源 + W3C Secure Contexts 认定的
  potentially-trustworthy **回环源**（localhost / 127.0.0.1 / ::1）；
  **remote** = 其它 http/https/ws/ftp；**opaque** = data:/blob:
  （自身不携带可信性，须**继承创建者** trust，未知按最保守的远程）；
  **unknown** = 空 / 无法解析，保守按远程（"判不出来"≠"可信"）。
- `ScriptTrustGate` 三态策略 `disable_all` / **`local_only`（默认）**
  / `allow_all`；按**源**（scheme://host[:port]，非整条 URL）显式
  `allow_origin(origin, reason)` / `revoke_origin`；策略切换与授权
  均带 reason 入**有界**审计轨迹（256），非法策略名被拒。
- 第 5 点 `ScriptIsolation`：ISO_NONE（脚本与 UI 同进程同线程，
  当前事实）/ ISO_WORKER_IPC（worker spawn + IPC 通，但脚本仍在
  主线程）/ ISO_OS_SANDBOX（OS 沙箱经验证，未实现）。
  **`is_security_boundary` 只由 `os_sandbox_verified` 决定**——
  spawn 了、IPC 通了都不构成安全边界。
  `ScriptIsolationClaim.is_truthful()`：worker_ipc 下"脚本已沙箱
  隔离"判不真实并给原因；未知能力 / 空事实保守按不真实。
- 约定：回环判为 local **不是绕过**——规范把回环当可信上下文，
  与"任意网络页面"是两类东西；这同时保住了既有回环测试服务器
  主链（B05 pending nav 测试就用 127.0.0.1）。

## R7-S02：统一 RequestContext + 无条件策略构建（2 提交）

### 探查结论（避免重复造轮子）

### 提交 1 `5d62a1f` — 纯逻辑层
新增 `toy_browser/network/request_context.py`（不发请求、不读时钟，
时钟由调用点注入）：
- `RequestContext` 全字段（方案第 1 点逐项）。**`with_base()` 只改
  base_url，绝不给 document_origin 赋值**；`base_rewrites_origin`
  把"<base> 指向异源"暴露为可观测差异。跨源判定含端口；空源按
  最保守的跨源处理。
- destination 八类 + mode/credentials 常量；`default_mode_for`
  （classic 无 crossorigin → no-cors；module / crossorigin → cors；
  fetch/XHR → cors；未知 → None 供调用点明确拒绝）。
- `evaluate_request()` 发送前判定：destination → mode → scheme →
  deadline → 混合内容 → CSP → CORS 顺序拒绝。https 文档里的 http
  **active** 资源（script/style/fetch/xhr/font）阻断，image 属
  optionally-blockable 只标记 `mixed_content`。同源**无需** ACAO；
  跨源 no-cors → opaque；cors → `requires_acao` + 预检标记。
  **不支持的模式明确拒绝**（原因含 `not silently downgraded`）。
- `for_redirect()`：逐跳追加 chain；跨源跳转凭据降级 omit + 剥离
  Authorization/Cookie（fetch §4.6）。
- `filter_response_headers()`：opaque 响应**无任何**可读头；cors
  过滤 forbidden response-header names。
